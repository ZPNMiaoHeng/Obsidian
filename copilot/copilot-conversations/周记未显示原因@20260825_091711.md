**ai**: 没有理解错，周记文件其实已经存在了——你在「最近更新」里应该能看到 [[Note/Weekly/2026-W35.md]]。问题出在查询的日期格式和实际文件名对不上。

原因有两点：

- 「创建/打开本周周记」按钮用的是 Moment.js：`moment().format("gggg-[W]ww")`，生成的文件名是 `2026-W35`（`gggg` = ISO 周年份，`ww` = 两位 ISO 周数）。
- 而「本周周记」的 Dataview 查询用的是 `dateformat()`，它底层是 **Luxon**。Luxon 里两位周数的 token 是 `WW`（一位是 `W`），并不认 `ww`。所以 `dateformat(date(today), "yyyy-'W'ww")` 实际输出是字面量 `2026-Www`，永远不等于 `2026-W35`，自然查不到。

另外建议把 `yyyy` 也换成 `kkkk`（Luxon 的 ISO 周年份），这样才和 Moment 的 `gggg` 语义一致，跨年时（比如 2027-W01 落在 2026 年底）也不会取错年份。

把「本周周记」查询改成这样即可：

```dataview
TABLE WITHOUT ID file.link AS "周记", dateformat(file.mtime, "MM-dd HH:mm") AS "最近更新"
WHERE file.name = dateformat(date(today), "kkkk-'W'WW")
```

两种日期库的 token 对照：

| 含义 | Moment（按钮创建） | Luxon（Dataview `dateformat`） |
| --- | --- | --- |
| ISO 周年份 | `gggg` | `kkkk` |
| 两位 ISO 周数 | `ww` | `WW` |

改完后重新运行一下 Dataview 查询，本周周记 [[Note/Weekly/2026-W35.md]] 就会正常显示出来了。
