**ai**: Day Planner 是 Obsidian 里非常实用的时间管理插件，核心功能是在**每日笔记**中可视化一天的时间轴。以下是完整的使用指南：

## 1. 安装
- 打开 Obsidian → 设置 → 第三方插件 → 关闭安全模式 → 浏览
- 搜索 “Day Planner” → 安装并启用

## 2. 两种使用模式

### 模式一：代码块模式（Command Mode）
在每日笔记中，用代码块包裹时间计划，每一行代表一个时间段和任务：

````markdown
```text
- [ ] 09:00 晨会
- [ ] 10:30 写周报
- [ ] 14:00 项目评审
- [x] 16:00 回复邮件
```
````

- 支持 `- [ ]`（未完成）和 `- [x]`（已完成）
- 时间格式为 `HH:MM`（24小时制）
- 也可以用 `09:00 - 09:30` 指定结束时间

### 模式二：任务列表模式（Checklist / Task Mode）
直接在每日笔记中使用带时间戳的待办事项：

```
## 今日计划
- [ ] 09:00 📅 晨会
- [ ] 10:30 📅 写周报
- [ ] 14:00 📅 项目评审
```

注意：任务模式需要在插件设置中启用，并且时间需要以**行首**形式出现（`09:00` 紧跟任务文字）。

## 3. 查看时间轴
- 命令面板（`Ctrl + P` / `Cmd + P`）→ 运行 `Day Planner: Show Day Planner Timeline`
- 右侧边栏会弹出时间轴视图，**当前时间**会以一条红线标记
- 点击时间轴上的任务可跳转到对应笔记

## 4. 关键设置建议
| 设置项 | 推荐值 | 说明 |
|--------|--------|------|
| Day Planner Mode | Command Mode 或 Checklist Mode | 二选一，Checklist Mode 可与其他任务插件联动 |
| Use emoji for status | 开启 | 用 ✅/⏳ 等图标显示完成状态 |
| Show calendar by week | 开启 | 在时间轴顶部显示周视图 |
| Status for completed/failed | 自定义 | 如 `✅`、`❌` |

## 5. 高级用法
- **与 Daily Notes 联动**：把计划代码块放在每日笔记模板（Templater / Templates）中，每天新建笔记自动带格式
- **与 Tasks 插件配合**：任务模式中可加入 `#task` 标签或截止日期，统一在 Tasks 查询中管理
- **快速添加任务**：命令面板运行 `Day Planner: Add a task to today's plan`，可快速追加计划项

## 6. 注意事项
- 代码块模式中，`- [ ]` 和任务文字之间要有**空格**
- 时间轴默认显示当天内容，跨天计划需手动修改日期标签
- 若计划写在非当日笔记中，可在代码块首行加 `date: 2026-08-19` 指定日期

**ai**: 右键点击 Calendar 的周标题（通常默认会弹出菜单，其中包含“Create weekly note”或“Open weekly note”）创建周报失败，这类问题最常见的原因和解决办法如下：

## 1. 未安装或未启用 Weekly Notes 相关依赖
Obsidian 的 Calendar 插件本身**不自带周笔记功能**，它依赖以下方式之一：
- 内置的 **Daily Notes** 核心插件（仅能创建日笔记，不能直接生成周笔记）
- 第三方插件 **Weekly Notes**（由 Obsidian 官方论坛开发者提供）
- 或 **Templater** 配合自定义命令

如果你只启用了 Calendar 而没有安装对应的周笔记插件，右键周标题就会没有反应，或者提示找不到命令。

**解决办法**：
- 安装并启用 [Weekly Notes](obsidian://show-plugin?id=weekly-notes) 插件（社区插件中搜索）。
- 或者使用 Templater 配置一个“新建周报”的模板和命令，然后在 Calendar 的右键菜单中挂钩（部分旧版 Calendar 可以直接调用命令）。

## 2. 未配置周笔记的存放路径或模板
即使安装了 Weekly Notes 插件，仍需在插件设置中指定：
- 存放周笔记的文件夹（如 `Weekly/`）
- 文件名格式（如 `YYYY-[W]ww` 表示 `2026-W33`）
- 是否使用模板（可关联一个模板文件）

如果文件夹不存在或模板路径错误，创建时会报错（常见于控制台显示 `ENOENT` 或 `TypeError`）。

**解决办法**：
- 进入插件设置，先创建对应的文件夹（如 `Weekly`），并填入正确路径。
- 如果指定了模板，确认模板文件存在且格式无误（不要用空模板或含非法字符的文件名）。

## 3. 文件路径或文件名包含非法字符
周笔记文件名格式如果包含 `/`、`\`、`:` 等字符，在 Windows 上会导致创建失败。默认的 `YYYY-[W]ww` 是安全的，但如果你改成了类似 `YYYY/WW` 这种带斜杠的格式，就会被解释为子目录，若该子目录不存在则会报错。

**解决办法**：把文件名格式改为 `YYYY-[W]ww` 或 `YYYY-MM-DD` 这类无斜杠的格式。

## 4. Obsidian 权限或同步问题
- Vault 位于云同步盘（如 OneDrive、iCloud、坚果云）且文件被占用或锁定时，创建可能失败。
- 当前系统用户没有对 vault 目录的写入权限。

**解决办法**：尝试在本地非同步目录新建一个临时 vault 测试是否还失败；检查文件夹属性中的写入权限。

## 5. Calendar 插件版本过旧或与 Obsidian 核心冲突
旧版 Calendar 可能不兼容新版 Obsidian（例如 v1.x 后 API 变化），导致右键菜单功能失效。

**解决办法**：更新 Calendar 插件（社区插件 → 更新），并确认 Obsidian 版本为最新稳定版。

## 6. 右键菜单弹出的选项不同导致误操作
- 如果右键周标题看到的是“复制日期”、“插入链接”等选项，而不是“create weekly note”，说明当前右键菜单并不是创建周报的入口。
- 正确入口通常在**周数字**（如 W33）上右键，而不是整个周条。

**解决办法**：鼠标移动到日历中左侧的周数字（如 `W33`）上，再右键，查看是否出现“Create weekly note”。
