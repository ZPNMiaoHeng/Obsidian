#7000N 

## 2 功能介绍

1. 描述 CAP_POOL 模块在项目架构中的位置，说明其耦合关系。
2. 描述 CAP_POOL 模块所实现的核心功能。

- CAP_POOL 模块位于 ES7000N 芯片 IPP 子系统内部，整合了 ICAP、VCAP、ECAP 的查表资源（含 slice 与 action 仲裁逻辑），实现资源共享。通过寄存器配置，可灵活决定 CAP slice 的资源分配和 action 仲裁策略。
- 一次查表（First Lookup）：ICAP/VCAP/ECAP 发起首次查表请求，将查表数据送入 CAP_POOL。模块根据寄存器配置选择 type，完成查找键值（Key）组装，并将查表结果返回至对应 CAP 模块。
- 二次查表（Second Lookup）：ICAP/VCAP/ECAP 发起二次查表请求，将组装好的模版数据送入 CAP_POOL。模块在对应 slice 中执行查表操作，查表结果依据 slice 优先级和配置进行仲裁；后续对 ICAP/VCAP/ECAP 的 action 行为冲突进行处理。
- 支持 slice 数据的搬移和删除操作。

### 架构与阵列相关

| 术语            | 说明                                   |
| ------------- | ------------------------------------ |
| **TCAM**      | 三态内容寻址存储器，支持 0、1、X（Don't Care）三种匹配状态 |
| **Data 阵列**   | 存储比较数据的 SRAM 阵列                      |
| **Mask 阵列**   | 存储掩码的 SRAM 阵列，与 Data 阵列配合实现三态编码      |
| **Valid Bit** | 每个条目关联的有效位，标记为无效的行直接跳过比较，降低动态功耗      |
| **Bank**      | 阵列的基本分区单元，通过 CBE 引脚独立使能              |

### 编码与比较逻辑

| 术语 | 说明 |
|------|------|
| **Data=0, Mask=0** | 编码为 **X**（Don't Care），比较时忽略该位 |
| **Data=0, Mask=1** | 编码为 **0**，要求 Key 在该位为 0 才匹配 |
| **Data=1, Mask=0** | 编码为 **1**，要求 Key 在该位为 1 才匹配 |
| **Data=1, Mask=1** | **Prohibited**（禁止状态），可作为错误检测 |
| **Match 逻辑** | `Match = (Data XOR Key) AND Mask` |

### 信号与引脚

| 术语          | 说明                            |
| ----------- | ----------------------------- |
| **MSKB**    | 码引脚，写入时逐位控制 Data 和 Mask 阵列    |
| **VBE**     | Valid 位阵列使能引脚，独立控制 Valid 位的操作 |
| **VBI**     | Valid 位输入引脚                   |
| **CBE**     | Bank 使能引脚，激活部分阵列进行比较          |
| **HITLINE** | 逐行匹配信号，延迟 1 cycle             |
| **HIT**     | 全局命中标志，延迟 2 cycles            |

### 配置与实例化

| 术语 | 说明 |
|------|------|
| **word** | 字数（深度），如 512 |
| **bit** | 位数（宽度），如 160 |
| **M+数字** | 宽高比编号，如 M1、M2 |
| **wordwrite (W1/W0)** | 写模式：W1 = 字写，W0 = 位写 |
| **busmode (F0/F1)** | 总线模式：F0 = 无总线模式，F1 = 带总线模式 |

### 特性

| 术语 | 说明 |
|------|------|
| **ECC** | 纠错码，用于检测和纠正存储数据错误 |
| **RST/FLUSH** | 批量复位/清零操作，常用于 Valid 位 |
| **Auto leakage control** | 自动漏电控制技术，降低静态功耗 |
