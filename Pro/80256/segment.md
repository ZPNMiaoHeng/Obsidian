# SPEC
- Segment
- Segment capture：是否从配置写入请求中捕获了有效的 Segment 值,  如第 2.2.6.2 节所述。
	- 当从 FM 中的配置写入请求捕获目标分段 （Destination Segment）字段时，该位必须设置为与请求一起接收的 DSV 位的值。
	- 当在 NFM 中接收到配置写入请求时，该位必须清除。
	- 请注意：
		- 当从功能到 RC 的路径上的每个链路都处于 FM 时,该位将被 设置。
		- 如果功能和 RC 之间的任何链路处于 NFM,则该位将被清除。 只有当此位被设置时,功能才应发起针对非自身层级的按 ID 路由消息请求。  在不支持 FM 的设备中,该位可以硬连线为 0b。 RC 中的请求方和完成方可以以特定于实现的方式知道其分段值,并且  可以表现为该位被硬连线为 1b。  交换机中的所有功能共享一个由配置写入请求设置的位,该位与上游  端口相关联的功能相关。  在捕获其分段值的功能中,默认值为零

# KIMI
### Segment 字段的作用

在 PCIe v6.0 中，Segment 字段被添加到事务层包（TLP）的头部，主要用于以下方面：

- **简化根复合体（Root Complex）的处理**：在 PCIe v6.0 之前的版本中，Segment Number（段编号）仅由根复合体和系统软件明确了解，PCIe 交换机或设备无法直接识别跨段的对等通信。这使得根复合体需要跟踪跨段的非发布请求，并在这些请求通过根复合体时替换事务 ID，增加了实现成本和降低了性能。而在 PCIe v6.0 中，Flit 模式下的 TLP 可以在头部明确指示段编号，从而无需根复合体对这些 TLP 进行“所有权”接管，简化了根复合体的处理逻辑，降低了实现复杂度和成本，提高了对等通信的性能。
    
- **支持跨段的事务路由**：Segment Number 可以唯一标识 PCIe 层次结构中的不同配置地址空间（BDF 空间）。通过在 TLP 头部包含段编号，交换机可以更准确地进行事务路由，确保事务能够正确地在不同的段之间传输，即使在复杂的多段系统中，也能保证数据包能够到达正确的目的地。
    
- **优化错误报告和调试**：Segment Number 的加入使得在高级错误报告（AER）功能中可以按段记录错误信息，有助于更精确地定位和分析错误，从而提高系统的可靠性和可维护性。
    

### Segment Capture 的含义

Segment Capture 是指 PCIe 设备在接收到特定类型的配置写请求（如 Type0 配置写请求）时，会捕获并记录其自身的段编号（Segment Number）。具体来说：

- 在非 Flit 模式下，所有端点（EP）功能需要从接收到的 Type0 配置写请求中捕获总线号和设备号。
    
- 在 Flit 模式下，端点功能还会捕获其自身的段编号。这样，每个功能都可以通过 Seg:Bus:Dev:Func 的形式被唯一标识，从而在系统中更准确地定位和识别各个设备。
    

这种机制使得设备能够更好地理解和处理跨段的事务，同时也为系统软件提供了更丰富的信息，以便进行更有效的资源管理和错误处理。


“Segment Clear”可能是指清除或重置 Segment 相关的配置或状态，以便重新配置或初始化 PCIe 设备的段信息。这可能用于在系统启动、设备重置或配置更改时，确保 PCIe 设备的段信息处于一致和正确的状态。
