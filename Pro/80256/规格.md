### Fabric 路由
- HIE 字段决定报文在 Fabric 路由中路由方式：
	- 静态路由：vDSP/vUSP 绑定的路由；
	- 动态路由：SPID/DPID 指定的 Fabric 路由方式；
- NTB/UIO 可以使用动态路由/静态路由； 
- host 的 PCIe 流量必须使用静态路由；

### No snoop
- 只要命中 NTB 功能就需要添加 clear no snoop 功能；

### ECRC
- 当前在 IP 出口实现，NTB 不关注；
- 只有自带 ECRC 的报文在出口会更改，不带 ECRC 不会添加的；

### 场景分析

- 报文第一次经过 NTB：
	- 未命中 NTB：
		- FNTB=1'b0，NFNTB=1'b0，NT_MC_HIT=1’b0；
	- 命中 NTB：
		- HBR：FNTB=1'b0，NFNTB=1'b1；
			- 单播、Doorbell：NT_MC_HIT=1’b0，PCIE_ROUTE 使用 dst_vcs；
			- NT 组播：NT_MC_HIT=1’b1，PCIE_ROUTE 使用 src_vcs；
		- PBR：FNTB=1'b1，NFNTB=1'b0；
- 报文在 Fabric 网络中：
	- 在 Ingress 中 DPID 未命中 FPort 后，报文走 PBR 路由；
	- NTB 检测到 FNTB == 1'b1，不做处理；
- 报文在 edge-Switch 经过 NTB：
	- 在 Ingress 中 DPID 命中 FPort 后，报文改为走 HBR 路由；
	- NTB 检测到 FNTB== 1'b1，不做处理；
- Fabric 网络中存在 HBR、PBR的场景：![[2-规格.png]]


### PBR 场景分析

- 正常情况下：
	- requester：
		- 从 sw8-->sw11 vcs6；
		- vcs6 经过 NTB 转换后到 vcs5，走的 HBR 路由；（当前架构，地址转换表中 DPID 无效，不管 ID 表中 SPID）
		- 报文就到了 EP 2c；
	- EP 2c 返回 Completion 报文：
		- 使用 id_index 查 ID 表时，==会存在 SPID 有效，但此时保存的sw_id=8，不是9，就会走 PBR 路由的==；
