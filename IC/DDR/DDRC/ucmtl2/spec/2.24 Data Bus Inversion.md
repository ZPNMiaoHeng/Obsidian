# DBI 概述
- 数据总线反转是 DDR4/LPDDR4 中特有降低功耗的功能
	- DDR4：逻辑 0 比逻辑 1 消耗更多功耗；
	- LPDDR4：逻辑 1 比逻辑 0 消耗更多功耗；
	- ==同时切换输出==；

- **功能实现**：
	- 如果一个字节中的 0（DDR4）或 1（LPDDR4）数量大于4，则对读写数据的每个字节进行取反操作；
	- 并使用一比特数据指示是否使用 DBI 功能；
	- 对于写操作，DBI 与 DM(data mask，数据掩码) 信号共享；对于读操作，使用 dfi_rddata_dbi 信号；

- DBI 功能只支持 x8 和 x16 设备，不支持 x4 设备。
- DDR4 中 DBI 和 DM 不能同时使用；==而 LPDDR4 支持同时使用，umctl2 将 dfi_wrdata 字节设置为 0xFF，并将 dfi_wrdata_mask 比特位设置为 0==；

- DFI 手册规定，DBI 可以在 DDRC 中实现，也可以在 PHY 中实现；
	- umctl2 中 DFIMISC.phy_dbi_mode 寄存器控制；
	- 若其值为 1 ，则 DBI 的功能在 PHY 中实现，DFI 接口上的读写数据与禁用 DBI 时相同（不允许 DM 功能），并且 dfi_rddata_dbi 信号将被忽略；
	- 若其值为 0，则 DBI 的功能在 umctl2 中实现，
		- 写操作期间，DBI 的值会被放置在 dfi_wrdata_mask 上；
		- 读操作期间，会对 dfi_rddata_dbi 进行评估，并用于确定是否需要对读取数据的值进行取反操作。

## DBI 配置寄存器
- DBICTL 寄存器三个字段功能：
	- rd_dbi_en：打开读 DBI；
	- wr_dbi_en：打开写 DBI；
	- dm_en：打开 DM；
	- DMD（Data Mask Disable，数据掩码无效）：在 LPDDR4 MR13 定义，与 DBICTL.dm_en 极性相反；

- 若使用读 DBI 功能，JEDEC 规范指出， DDR4 的 CL（CAS Latency）或者 LPDDR4 的 RL（read Latency）必须增加。因此 umctl2 寄存器需要根据 CL 或 RL 进行调整
	- DFITMG.dfi_t_rddata_en；
	- DRAMTMG.read_latency；
	- DRAMTMG.rd2wr；
	- DFITMG.dfi_tphy_rdcslat；
	- INIT4.emr2（LPDDR4 only）；
	- INIT6.mr5（DDR4 only）；

- 若 DDR4 选择了非零的 AL，这也同样取决于 CL。在更新寄存器之前需要进入**自刷新模式**，因为 DFITMG0.dfi_tphy_wrlat 是第二种类型寄存器（quasi-dynamic Register，准动态寄存器）。
	- DFITMG0.dfi_tphy_wrlat 
	- DRAMTMG0.wr2pre
	- DRAMTMG1.rd2pre
	- DRAMTMG2.write_latency
	- DRAMTMG4.t_rcd

## DBI 启用和禁用步骤

1. 进入用于写入准动态寄存器的适当模式。如果为DDR4选择了非零的AL，则需要进入自刷新模式；
2. 按需设置 DBICTL.rd_dbi_en 和 DBICTL.wr_dbi_en；
3. 设置 DRAM MR（Mode Register） 以匹配先前的设置；
4. 为 DDR4 调整 MR0 中的 CL ，对于LPDDR4则无需更改；
5. 根据 CL（或RL）和 AL（前面已列出）适当地调整寄存器；
6. 通过退出**自刷新模式**或重新启用读写流量来退出准动态模式。
