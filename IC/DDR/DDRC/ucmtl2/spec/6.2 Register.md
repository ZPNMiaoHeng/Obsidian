# Spec
- 本节概述了在何种情况下可以对 APB 寄存器进行写入操作。
- 大多数寄存器（static，静态寄存器）会在 umctl2 处于复位状态（core_ddrc_rstn = 0）时进行初始化，之后不会再进行更改。下文列出例外情况下的寄存器。
- umctl2 解复位之前，必须有 core_ddrc_core_clk 时钟。
- 内存映射是一种由不同块组成的分层结构，部分寄存器会在多个模块中实例化，寄存器标识使用**块名.寄存器名**。
- 在第五章 Register Descriptions 中指定了寄存器的类型，分为 static、dynamic、quasi dynamic。
## 6.2.1 Dynamic Registers

- 在 umctl2 运行期间，动态寄存器可以随时写入；
- APB 模块与 umctl2 处于不同时钟域，动态寄存器的值首先会同步到 umctl2 的时钟域；静态寄存器不需要同步；
### 6.2.1.1 Refresh Related Registers

- 刷新相关寄存器是动态的，但更新需要执行以下步骤：
	- 根据需求更改与刷新相关的寄存器；
	- 在确定更改后的寄存器稳定后，翻转 RFSHCTL3.refresh_update_level。
		- 此寄存器字段功能是当保存信号发生翻转，表示相应的所有与刷新相关的寄存器值已被更新；
		- 通过这种机制来避免在目标时钟域中出现采样错误，同时允许控制器在与刷新相关的时序寄存器发生变化时进行特殊处理（比如：在需要时发出额外的刷新信号并重置刷新定时器）。

- 在第五章中，可更新的刷新相关寄存器被标记为` Dynamic-Refresh Related`。

---
#### 特殊刷新寄存器
- RFSHCTL*.refresh_timer*_ start_value_x32 寄存器只能在初始化期间进行编程;
- RFSHCTL3.refresh_mode 只能在初始化期间或控制器处于自刷新模式时进行编程;
	- 初始化时,需要将 RFSHCTL3.refresh_mode 设置为==与通过 INIT.emr3 写入 SDRAM 的MR3 刷新模式字段相匹配==;
	- 自刷新模式下,==SRX== 之后会自动发送相应的 MR3 命令。==但还需要修改 INIT.emr3，因为通过 MR3 命令写入 SDRAM 的值取自 INIT.emr3，而非 RFSHCTL3.refresh_mode。==
## 6.2.2 Quasi Dynamic Register

- 每种类别都要求满足特定条件，在满足特定条件后，需要将 SWCTL.sw_done 寄存器写 b0，从而启用软件编程。
- 如果 UMCTL2_OCCAP_EN =1 且 OCCAPCFG.occap_en =1，则必须将SWSTAT.sw_done_ack 读取为 1’b0。
- 寄存器编程完成后，必须将 SWCTL.sw_done 置为 1‘b1，并读取 SWSTAT.sw_done_ack 为1’b1。
	- 这是为了确保准动态寄存器能够正确传播到目标时钟。

### 6.2.2.1 Group 1: Registers that can be Written when No Read/Write Traffic is Present at the DFI

1. 通过将 DBG1.dis_dq 寄存器置 1‘b1；
2. 并轮询 DBGCAM.wr_data_pipeline_empty 和 DBGCAM.rd_data_pipeline_empty1 ；
	1. 可以防止在DFI上发送任何读写流量。
	2. 此外，如果通过 CRCPARCTL1.crc_parity_retry_enable 启用了 DDR4 重试功能，则需轮询 CRCPARSTAT.cmd_in_err_window，直到其值等于 0。
	3. 如果通过 CRCPARCTL1.alert_wait_for_sw 启用了软件干预，在轮询期间还需监控 CRCPARSTAT.dfi_alert_err_int 和 CRCPARSTAT.dfi_alert_err_fatl_int。
	4. 如果在轮询完成之前其中一个或多个被置位，则必须在后续步骤之前完成重试过程。
3. 在这种模式下，向组1寄存器写入数据是安全的。

- 通过将 DBG1.dis_dq 写为 1’b0 来重新启用流量。

### 6.2.2.2 Group 2: Registers that can be Written in Self-refresh, DPD, and MPSM Modes

- 当 uMCTL2 通过软件（PWRCTL.selfref_sw）进入自刷新模式后，DFI 总线将保持空闲状态，直到软件退出自刷新模式。对于 mDDR、LPDDR2 和 LPDDR3 的深度掉电模式（DPD），以及 DDR4 的最大节能模式（MPSM），情况同样如此。
- 在这种模式下，写入第2组寄存器是安全的。通过将PWRCTL.selfref_sw写入1’b0来重新启用流量。
#### 注意
- 对于自刷新，通过检查 STAT.operating_mode =3’b011 和 STAT.selfref_type =2’b10 ，确保自刷新不是由“仅自动自刷新”引起的。
	- 如果通过 CRCPARCTL1.crc_parity_retry_enable 启用了 DDR4 重试，并且通过 CRCPARCTL1.alert_wait_for_sw 启用了软件干预，则在轮询 STAT.selfref_type 期间，还需监控 CRCPARSTAT.dfi_alert_err_int 和 CRCPARSTAT.dfi_alert_err_fatl_int 。
	- 如果在轮询完成前其中一个或多个信号被置位，则必须在后续步骤之前完成重试程序。
	- 在本节中，提及的自刷新是指自刷新（非LPDDR4）或SR掉电（LPDDR4）。
- 对于 MPSM，在更改任何所列寄存器之前，要确保 STAT.operating_mode =3’b110。如果通过 CRCPARCTL1.crc_parity_retry_enable 启用了DDR4重试，则轮询 CRCPARSTAT.cmd_in_err_window ，直到其等于0。
	- 如果通过 CRCPARCTL1.alert_wait_for_sw 启用了软件干预，则在轮询期间还需监控 CRCPARSTAT.dfi_alert_err_int 和 CRCPARSTAT.dfi_alert_err_fatl_int。
	- 如果在轮询前其中一个或多个信号被置位，则必须在后续步骤之前完成重试程序。
- 对于 DPD，在更改任何所列寄存器之前，要确保 STAT.operating_mode =3’b110。
- 对于 DPD/MPSM，STAT.operating_mode =3’b1xx，但进入/退出和模式本身可按以下方式区分： 
	- operating_mode =3’b101 — 正在进行 DPD/MPSM 进入操作;
	- operating_mode =3’b110 — 已进入 DPD/MPSM 模式;
	- operating_mode =3’b111 — 正在进行 DPD/MPSM 退出操作;
- 第2组寄存器可以在 DPD/MPSM 中更新，但尚未进行全面测试。
### Group 3: Registers that can be Written When Controller is Empty

- 对于多端口配置，PCTRL_n.port_en 用于启用或禁用每个端口的输入流量。
	- 可以先从 PSTAT 寄存器（wr_port_busy_n 和 rd_port_busy_n位域）轮询控制器空闲状态，且应该读取到 `PSTAT ==32’b0`（不忙）。
	- 向 SBRCTL.scrub_en 写入 ’0’，以禁用 SBR（仅在实例化 SBR时需要）。
	- 轮询  SBRSTAT.scrub_busy =0，表示没有未完成的 SBR读命令（仅在实例化 SBR时需要）。
	- DBG1.dis_hif用于启用或禁用流向控制器的输入流量。
	- 然后，必须轮询 DDRC CAM/pipeline 的空状态`（(DBGCAM.dbg_wr_q_empty ==1’b1) && (DBGCAM.dbg_rd_q_empty ==1’b1) && (DBGCAM.wr_data_pipeline_empty ==1’b11) && (DBGCAM.rd_data_pipeline_empty ==1’b1)）`。
	- 此外，如果通过 CRCPARCTL1.crc_parity_retry_enable 启用了 DDR4 重试功能，则轮询 CRCPARSTAT.cmd_in_err_window，直到其等于0。
	- 如果通过 CRCPARCTL1.alert_wait_for_sw 启用了软件干预，则在轮询期间监控  CRCPARSTAT.dfi_alert_err_int 和 CRCPARSTAT.dfi_alert_err_fatl_int。
	- 如果在轮询完成之前其中一个或多个被置位，则必须在后续步骤之前完成重试过程。
- 在这种模式下，向第 3 组寄存器写入数据是安全的。
- 如果仅使用 HIF，则通过向 PCTRL_n.port_en 或 DBG1.dis_hif 写入 1’b1 来启用流量。如果需要，通过向 SBRCTL.scrub_en 写入 1’b1 来启用 SBR（仅在实例化 SBR时需要）。
### Group 4: Registers that can be Written Depending on MSTR.frequency_mode and MSTR2.target_frequency

- 当 MSTR.frequency_mode =0 且/或 MSTR2.target_frequency =0时，向块 UMCTL2_REGS_FREQ1、UMCTL2_REGS_FREQ2 和 UMCTL2_REGS_FREQ3 中的寄存器写入数据是安全的。
- 当 MSTR.frequency_mode =1 且 MSTR2.target_frequency =1 时，向块 UMCTL2_REGS、UMCTL2_REGS_FREQ2 和 UMCTL2_REGS_FREQ3 中的寄存器写入数据是安全的。
- 当 MSTR.frequency_mode =1 且 MSTR2.target_frequency =2 时，向块 UMCTL2_REGS、UMCTL2_REGS_FREQ1 和 UMCTL2_REGS_FREQ3 中的寄存器写入数据是安全的。
- 当 MSTR.frequency_mode =1 且 MSTR2.target_frequency =3 时，向块 UMCTL2_REGS、UMCTL2_REGS_FREQ1 和 UMCTL2_REGS_FREQ2 中的寄存器写入数据是安全的。
