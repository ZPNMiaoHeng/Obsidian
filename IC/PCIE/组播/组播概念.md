
## 基本概念

组播能力结构定义了组播的地址范围，该地址范围被等分为大小相同的 N 个组播窗口，一个组播窗口被称为一个组播组（Multicast Group，MCG）。

每个支持组播的 Function 都应实现该组播能力结构，以提供事务的路由方向、决定每个 MCG 的事务接收或透传。

## PCIe 组播事务处理
### 组播事务触发与路由

- PCIe 组播事务需满足以下三个条件：
	1. MC_enable 置 1；
	2. 所发送 TLP 为存储器写或地址路由的消息，两者均为转发请求；
	3. ==TLP 中地址在几个 MCG 内存空间范围内，即 MC_Base_Addr <= AddrTLP < (2MC_Index_Position * (MC_Num_Group+1))==。

- PCIe 组播操作只支持 Posted 请求，若 Non-Posted 请求地址刚好在某个 MCG 地址范围内，这仍然不是一个组播操作，扔应按照单播的处理方式对齐进行处理。
- 组播操作规则：
	- 从 TLP 地址中提取组播组号 MCG；
		- MCG=((AddressTLP - MC_Base_Address) >> MC_Index_Position) & 3Fh，
		- 其中 MC_Base_Address 及 MC_Index_Position 可以采用任何一个 Function 中该域的值%%好像这两个的值都是相同的%%。
	- 根据 MC_Block_All 及 MC_Block_Untranslated 域比特向量的值来检查提取的 MCG：
		- Switch 及 RP 采用入端口的 MC_Block_All/MC_Block_Untranslated 值检测入端口组播 TLP；
		- EP Function 采用其 Function 内的 MC_Block_All/MC_Block_Untranslated 值来检测待发的组播 TLP。
		- 组播阻塞 TLP 处理：
			- 当 MCG 中存在 MC_Block_All 要阻塞的 TLP；
			- 当 MCG 中存在 MC_Block_Untranslated 要阻塞的 TLP，且 TLP 中的地址为未转换地址（根据头标 AT 域判断）。

### MC_Overlay 机制
- 有些 EP 只有一个 BAR，不具备组播能力结构。为了让单 BAR EP 能够同时接收单播事务及组播事务，可以采用 MC_Overlay 机制来实现。具体实现方法为：
	1. 软件配置 Switch 下行端口的 MC_Overlay_BAR 来启动 MC_Overlay 机制，把全部或部分组播地址映射到 EP BAR 地址范围；
	2. 在 Switch 上行端口，MC_Overlay 机制可用于把组播地址范围的一部分重映射为主内存相关联的存储空间。 
- 开启了 MC_Overlay 机制，Overlay 操作会把组播 TLP 地址中比特数大于等于 MC_Overlay_Size 的部分替换为 MC_Overlay_BAR 中的对应比特。
	- Egress_TLP_Addr=(MC_Overlay_Size<6)?Ingress_TLP_Addr:{MC_Overlay_BAR[63:MC_Overlay_Size], Ingress_TLP_Addr[MC_Overlay_Size-1:0]}
