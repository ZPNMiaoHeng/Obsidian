#PCIe #spec 

# ACS 功能
## ACS source validation（V）
使能后，**下游端口会检查 upstream 方向的 Request TLP（例如 Mwr/Mrd）的 Request ID 字段的 Bus Num，判断 Bus Num 是否在该下游端口 Sec_Bus 和 Sub_Bus 之间**。
- 若在正常路由该报文，否则认为出现 ACS 违例，丢弃该报文并上报 ACS 违例错误。
- 该功能在 vPPB 与 PPB 一一绑定时可以由控制器实现。
- 该规则不会影响 completion 报文。

## ACS Translation Blocking（B）
使能后，**下游端口会检查 upstream 方向的 Request TLP 的 AT 字段是否为默认值 2’b00**。
- 若是，则正常路由该报文；若否，则丢弃该报文并上报 ACS 违例。
- 该功能在 vPPB 与 PPB 一一绑定时可以由控制器实现。
- 该规则不会影响 Completion 报文。

## ACS P2P Request Redirect（R）
使能后，**该下游端口会将其产生的 peer-to-peer Request TLP 的路由目的端口转向 RC，即原本发给其他下游端口的 Request TLP 会发给上游端口**。
- 该部分逻辑由路由模块实现。
- 该规则不会影响 Completion 报文。

## ACS P2P Completion Redirect（C）
使能后，**该下游端口会将其产生的 peer-to-peer Completion TLP 的路由目的端口转向 RC，即原本发给其他下游端口的 Completion TLP 会发给上游端口**。
- 该部分逻辑由路由模块实现。
- 该功能主要配合 R 规则适用，防止违背 PCIe 报序。

## ACS Upstream Forwarding（U）
使能后，**该下游端口会将目的地址命中自身 Base/Limit 的 upstream 方向 Request TLP 或目的 ID 命中自身 Sec_Bus/Sub_Bus 的 upstream 方向 Completion TLP 发送给上游端口**。
- 正常情况下，命中稀有端口自身的 Base/Limit 或 Sec_Bus/Sub_Bus 窗口的 upstream 方向的 TLP 应该做 UR 处理。使能 ACS U 规则后，该报文可以转发到上游端口。
- 该功能需要控制器和路由模块共同实现。

## ACS P2P Egress Control（E）
该能力**可以选择性的使某些下游端口支持 peer-to-peer 转发，而另一些端口不支持**。**ACS 能力寄存器中包含 P2P Egress Control 向量，每个 bit 对应一个端口**。
- 若该端口配置为支持 peer-to-peer，则该报文正常处理，且会受到 R 规则影响。
- 若该端口配置为不支持 peer-to-peer 转发，当发生 peer-to-peer 传输时，丢弃报文作为 ACS 违例处理。
- 该规则不会影响 Completion 报文。

## ACS Direct Translated P2P（T）
使能时，**若下游端口收到 AT 字段标记为 Translated 的 upstream 方向的 Request TLP，如该 TLP 地址在同一个 PCIe domain 下游端口的窗口中，直接进行 peer-to-peer 传输，而不再需要考虑上述 ACS R 和 E 规则**。
- 该功能在路由模块实现；
- 该规则不会影响 Completion 报文。
