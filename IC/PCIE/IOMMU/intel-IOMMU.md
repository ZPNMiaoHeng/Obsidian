# DMA 重映射 
 
本章介绍了直接内存访问（DMA）重映射的硬件架构。该架构设想将硬件重新配置为以下形式：将Root-Complex 其集成到处理器核心模块中，或者置于核心逻辑芯片组组件内。
##  3.1 DMA 请求的类型
重映射硬件将来自根复合体集成设备和 PCI Express* 连接的独立设备的内存请求分为两类：
- **无地址空间标识符的请求**：这些是来自端点设备的常规内存请求。这些请求通常指定访问类型（读/写/原子操作）、目标 DMA 地址/大小以及发起请求的设备的源 ID（例如总线/设备/功能）。
- **有地址空间标识符的请求**：这些是来自端点设备的带有额外信息以标识目标地址空间的内存请求。除了常规请求中的属性外，这些请求还指定目标进程地址空间标识符（PASID），以及可选属性，例如执行请求（ER）标志（用于指示为指令访问的读取）。 
详情请参阅 PCI Express 规范中的进程地址空间 ID（PASID）功能。

## 3.3 重映射硬件 - 软件视图
重映射架构允许支持单个 PCI 段组的硬件实现向软件展示重映射功能，既可以作为一个覆盖整个 PCI 段组的单一硬件单元，也可以作为多个硬件单元，每个硬件单元支持 PCI 段组层次结构中互斥的设备子集。例如，一种实现方式可以展示一个重映射硬件单元，支持根总线上的一个或多个集成设备，以及针对一个或一组 PCI Express 根端口后方设备的额外重映射硬件单元。平台固件（BIOS）向软件报告平台中的每个重映射硬件单元。第 8 章描述了通过 ACPI 结构进行报告的结构。对于支持多个 PCI 段组的硬件实现，重映射架构要求硬件为每个段组的 I/O 层次结构中产生的请求展示独立的重映射硬件单元（每个段组至少一个）。

### 3.4.1 源标识符
出现在地址转换硬件上的每个入站请求都需要标识发出请求的设备。在本文档中，标识 I/O 事务发起者的属性称为“源标识符”。重映射硬件可以通过实现特定的方式确定事务的源标识符。例如，某些 I/O 总线协议可能在每个 I/O 事务中提供发起设备的身份。在其他情况下（例如对于根复合体集成设备），源标识符可能基于根复合体的内部实现来推导。
对于 PCI Express 设备，源标识符是 PCI Express 事务层头中的请求者标识符。设备的请求者标识符由其 PCI 总线/设备/功能号组成，由配置软件分配，并唯一标识发起请求的硬件功能。图 3-2 展示了由 PCI Express 规范定义的 Requester-id1。

# 4.设备TLB支持 
## 4.1 设备TLB 操作 
设备-TLB 在终端设备中的支持需要标准化机制来实现以下功能：
- 向根复合体请求并接收转换。
- 表明内存请求（带或不带 PASID）是否有经过转换或未转换的地址。
- 清除设备-TLB 中缓存的转换信息。

## 4.1.1 Translation Request
不带 PASID 的翻译请求指定了以下由重映射硬件用于处理请求的属性：
- Address Type（AT）：
	- AT 字段的值为 01b，以标识其为翻译请求。
- Address：
	- 地址字段指示请求进行翻译的起始输入地址。
- Length：
	- 长度字段指示针对此请求可能返回的连续翻译的数量。 每个翻译的长度为 8 个字节。 长度字段必须始终指示偶数个 DWORD（以最小值 2（DW）计），且必须为偶数。 如果长度字段的值大于 2，则返回的额外翻译（如果在翻译响应中返回）是对于从请求的输入地址开始的依次递增的等大小页面。 有关更多详细信息，请参考 PCI Express 基础规范第 4.0 版或更高版本中的 ATS 规范。
- No Write（NW）标志：
	- 当 NW 标志设置时，表示端点是否请求此翻译的只读访问权限。

带 PASID 的翻译请求与上述请求具有相同的属性，并且还在 PASID TLP 前缀中指定了其他属性（PASID 值、执行请求（ER）标志以及特权模式请求（PR）标志）。

### 4.1.2 Translation Completion
如果重映射硬件无法成功处理翻译请求（无论是否包含 PASID），则会返回无数据的翻译完成结果。
- 如果重映射硬件被配置为不支持来自此端点的翻译请求，则在完成结果中会返回状态码 UR（不支持请求）。
- 如果重映射硬件在处理翻译请求时遇到错误，则会返回状态码 CA（完成者终止）。

如果重映射硬件能够成功处理翻译请求，则会返回包含数据的翻译完成结果。对于无 PASID 的成功翻译请求，翻译完成数据中的每个翻译都会指定以下属性：
- Size（S）：
	- “Size”字段中的“0b”值表示该翻译是针对 4KB 页面的。如果“Size”字段为 1 字节，则翻译的大小由转换地址字段中的最低位（位 63 至 12）决定，其值为 0。例如，如果位 12 为 0，则该翻译适用于 8KB 页面。如果位 12 为 1 且位 13 为 0，则该翻译适用于 16KB 页面，依此类推。请参考 PCI Express 基础规范（修订版 4.0）中的地址转换服务（ATS），以获取有关转换大小编码的详细信息。
- Non-Snooped 访问标志（N）：
	- 当设置时，非窥探访问字段表示使用此转换的转换请求必须清除请求未转换访问标志中的“No Snoop“属性。
- Untranslated 访问标志（U）：
	- 当设置时，转换的输入地址范围仅可由使用未转换请求的端点进行访问。
- Read permission（R）：
	- 若设置，则授予此转换的输入地址范围读取权限。若清除，则不授予此转换的输入地址范围读取权限。 
- Write permission（W）：
	- 若设置，则授予此转换的输入地址范围写入权限。若清除，则不授予此转换的输入地址范围写入权限。
- Translated Address：
	- 如果 R 或 W 字段被设置，而 U 字段被清零，则转换后的地址字段将包含针对相应输入地址的转换结果。端点可以通过带有此地址的转换请求来访问页面。

对于带有 PASID 的成功转换请求，转换完成数据中返回的每个转换都会包含与上述相同的属性，此外还有以下属性：
- Execute permission（EXE）：
	- 如果 EXE=R=1，则为该转换的输入地址范围授予执行权限。否则，不为该转换的输入地址范围授予执行权限。
- Privilege Mode Access（PRIV）：
	- 如果设置，则 R、W 和 EXE 指的是与特权模式访问相关的权限。如果清零，则 R、W 和 EXE 指的是与非特权访问相关的权限。
- Global Mapping（G）：
	- 如果设置，则该转换在该端点的所有 PASID 上都是通用的。如果清零，则该转换仅针对关联的转换请求中的 PASID 前缀中指定的 PASID 值而特定。
	- 对硬件进行重新配置可使该字段的值变为0。

### 4.1.3 Translated Request 
翻译后的请求是常规的内存读/写/原子操作请求，其地址类型（AT）字段值为 10 位。在向给定输入（未翻译）地址生成请求时，端点可能会在本地设备 TLB 中查找缓存的转换（前一次转换请求的结果）以获取该输入地址的缓存转换。如果找到了具有适当权限和特权的缓存转换，则端点可以生成一个翻译后的请求（AT=10 位），并指定从设备 TLB 查找中获得的转换地址。翻译后的请求以无 PASID 的请求形式发出。 

### 4.1.4 无效化请求和完成 
无效化请求由软件通过重新映射硬件来发出，以无效化缓存在端点设备 TLB 中的转换。无 PASID 的无效化请求指定以下属性： 
- Device ID
	- 设备（总线/设备/功能）的标识，其设备 TLB 是无效化的目标。 
- Size（S）：
	- “Size”字段中的 0b 值表示无效化的目标是 4KB 的输入地址范围。如果“尺寸”字段的值为 1b，则要失效的输入地址范围由未转换地址字段中的最低位（位 63 至 12）决定，其值为 0。有关无效地址大小编码的详细信息，请参阅 PCI Express ATS 规范。
- Untranslated Address
	- 指定要失效的输入（未翻译）地址范围的基址;

### 4.2.1 ATS 协议错误的处理 
以下上游请求总是被硬件处理为“不支持请求”（UR）：
- 带有 AT 字段值为“保留”（11b）的内存读取或写入请求（无论是否带有 PASID）。
- 带有 AT 字段值为“转换请求”（01b）的内存写入请求（无论是否带有 PASID）。
- 带有 AT 字段值为“转换”（10b）的带有 PASID 的请求。 

以下的上游请求（无论是否带有 PASID）在处理时总是被视为格式错误的数据包：
- 带有“Translation Request”这一 AT 字段值的内存读取请求，且具有以下任意一种情况：
	- 长度指定为奇数个 DWORD（即长度字段的最低有效位不为零）；
	- 长度大于 RC 支持的读完成边界（RCB）的 N/4 个 DWORD（其中 N 是读完成边界值（RCB）的大小，以字节为单位）；
	- 第一个和最后一个 DWORD 字节使能（BE）字段不等于 1111b。
- “Invalidation Request”消息。

当重映射硬件被禁用（全局状态寄存器中的 TES 为 0）时，以下上游请求被视为“不支持请求”（UR）。
- 具有非零 AT 字段的内存请求（即 AT 字段并非“未翻译”）。
- ATS “Invalidation Request”消息

### 4.2.2 ATS 地址类型中的 Root-Port 控制
支持访问控制服务（Access Control Services，ACS）功能的根端口能够支持“Translation Blocking”控制，以阻止在 AT 字段中具有非零值的上游内存请求。启用此功能后，此类请求将被接收端根端口报告为 ACS 违规。有关更多详细信息，请参阅 PCI Express 规范中的 ACS 能力部分。导致 ACS 违规的上游请求在根端口处被标记为错误并被阻止，不会传递给重映射硬件。
