
## MSI/MSI-X 介绍

- MSI/MSI-X 中断请求发生时，PCIe 设备会实际产生 1 个 Memory Write Transaction。
	- 对应的数据封包为 **Memory Write** 类型的 TLP
	- 其中目标 Memory Address 称为 **“Message Address”**，要写入该内存地址的数据称为 **“Message Data”** 。这两个字段都来自 MSI/MSI-X Capability Structure 中的设定，系统软件在 Enable 并初始化 MSI/MSI-X 的过程中必须要预先设置好它们。

## MSI vs MSI-X 能力架构

### 1.Capability结构组成

PCI/PCIe 设备通过在其 PCI Configuration Space 中实现 MSI/MSI-X Capability Registers来向系统软件表明是否支持 MSI/MSI-X。MSI/MSI-X Capability Registers 属于传统的 Basic PCI Capability Structure，其组成包括：
- 标准的 Basic PCI Capability Header (1-byte Capability ID + 1-byte Next Cpability Pointer)
- Capability-specific Registers (根据Capability ID不同而变化)

### 2.Capability-specific Registers  
  
虽然这部分寄存器的定义和位置在 MSI/MSI-X Capability 中不尽相同，但从功能角度来看都包含如下要素：
- Message Control：用来打开/关闭 MSI/MSI-X 功能；
- Message Address & Data: 用来指定 MSI/MSI-X 中断对应的 Message Address 和 Message Data；
- Vector Masking & Pending Status: 用来屏蔽 MSI/MSI-X 中断请求并反映中断 Pending 状态；

### 3.PVM 工作机制

PVM 的全称是 Per Vector Masking，它提供按 MSI/MSI-X 中断向量来屏蔽中断的功能。
当 Mask Bits 中某个位为 1 时，如果 PCIe 设备正好需要发送这种类型的中断请求，Pending Bits 中的同样位会被设备置 1，表示这个中断被 Pending 了，此时 PCIe 设备不会发送 MSI/MSI-X Memory Write Transaction 报文。当系统软件将 Mask Bits 中的对应位从 1 设置为 0 时，PCIe 设备才会发送 MSI/MSI-X Memory Write Transaction 报文向处理器提交中断请求，同时将 Pending Bits 中的同样位清 0。
通过 MSI/MSI-X 机制提交中断请求的方式类似于边沿触发方式，在这种方式下处理器可能会**丢失某些中断**。因此在设备驱动程序的开发过程中，可能需要结合使用 Mask Bits 和 Pending Bits 来防止这点。

从中，我们可以看到 MSI-X 从设计上解决了 MSI 存在的以下不足：
- MSI 机制只允许每个 PCI Function 最多拥有 32 个中断向量，这对某些应用来说完全不够；
- MSI 机制下每个 PCI Function 的所有中断向量都共用 1 个 Message Address，无法将其分配到不同 CPU 以实现中断服务在 CPU 间均衡分配；
- MSI 机制下每个 PCI Function 的所有中断向量都是连续的，在某些平台连续的中断向量意味着同样的中断优先级，无法满足区分中断优先级的需求。
