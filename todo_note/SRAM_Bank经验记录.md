# SRAM Bank 拆分设计指南

> **核心结论**：按深度拆分可降低动态功耗、提升工作频率，但会增加面积与静态功耗；"拆一半"（N=2）是常见经验折中点，但不能普适所有情况，需结合 PPA 目标量化决策 [^1]。

## 1. 概述

在数字电路设计中，当需要实现大容量查找表或缓存时，常因单块 SRAM IP 核的规格限制，需要将整张表拆分为多个独立的 SRAM Bank 来实现。这不仅是绕过 IP 限制的必然选择，更是一种能带来功耗、性能和灵活性收益的优化策略。

本文档分析 SRAM Bank 拆分对**面积**、**功耗**、**性能**的影响，涵盖拆分方向选择、地址映射策略、收益与风险，并给出工程实践建议与设计自查清单。

## 2. 拆分方向选择

### 2.1 按深度拆分（工程推荐方向）

将大表按深度（行数）均分为多个 Bank，每次访问仅激活目标 Bank。

| 指标 | 变化趋势 | 说明 |
|:-----|:--------:|:-----|
| 动态功耗 | **↓ 减小** | 每次仅激活 1 个 Bank，无需为整块大阵列供电 [^1] |
| 工作频率 | **↑ 提升** | 更小的 Bank 尺寸缩短位线长度，减少寄生负载，利于时序收敛 [^2] |
| 面积 | **↑ 增大** | 外围电路（行译码器、列选择器、灵敏放大器、写驱动等）重复 [^1] |
| 总 Leakage | **↑ 增大** | 总晶体管数增加 [^1] |
| Standby 功耗 | **↑ 增大** | 更多 Bank 需保持准备就绪 [^1] |

> 动态功耗与 Standby 功耗的净收益，需结合工作频率和有效访问频率综合评估 [^1]。

### 2.2 按宽度拆分（应避免）

宽度拆分后，单次访问仍须激活全部 Bank 才能获取完整数据，**动态功耗无任何节省**，却仍要付出外围电路复制带来的面积与静态功耗代价——**双输**，工程中应避免 [^1]。

> **例外说明**：若拆分目的不是降低功耗，而是绕过单块 IP 宽度上限或做端口扩展（如 1R1W 拆为两个单口 macro），则宽度切片仍属必要 [^5]。

### 2.3 端口维度补充

端口类型（SPRAM / TPRAM / DPRAM）是 table 层的定义属性，但直接影响拆分策略与 macro 选型 [^5]。选型时应遵循：**同等规格下能选 SPRAM 就不要选 TPRAM**，后者面积约为前者的两倍 [^7]。

## 3. 地址映射策略

将大表拆分为多 Bank 后，最核心的问题是如何将地址映射到具体的 Bank。主要有以下三种方案 [^1]：

| 方案 | 实现方式 | 优点 | 缺点 | 适用场景 |
|:-----|:---------|:-----|:-----|:---------|
| **低位交叉** | 用地址最低的 N 位选择 Bank | 连续地址轮换分布，顺序访问并发度高；逻辑开销几乎为零 | 对"步长=2^N"的访问模式敏感，易产生 Bank 冲突 | 流式处理、视频像素等顺序访问场景 |
| **高位交叉** | 用地址最高的 N 位选择 Bank | 地址空间连续，软件管理友好 | 局部性访问时并发度极低 | 分区管理、多任务隔离场景 |
| **哈希映射** | 将地址多位进行异或等运算后选 Bank | 有效打散不规则访问，抗冲突能力强 | 需额外逻辑门，破坏顺序访问的轮换特性 | 随机查表、路由查找、数据库索引等场景 |

> **设计建议**：优先分析实际工作负载的地址访问模式。若以顺序流式访问为主，直接用低位交叉是最优解；若为高随机性跳转访问，考虑引入轻量级哈希（如 XOR）以提升有效带宽 [^1]。

## 4. 面积影响

Memory 拆分得越细，面积增大的原因主要来自三个部分 [^1]：

1. **Memory 本身面积增大**：将一块大的 SRAM 拆成多个小的 SRAM，每个小 Bank 都需要独立的**外围电路**（行译码器、列选择器、灵敏放大器、写驱动等）。这些外围电路的总晶体管数远大于单块大 SRAM 的外围电路，导致总面积增加。
2. **PR 摆放的间隙开销**：多个独立的 Bank 在物理布局时，无法像单一大块 SRAM 那样紧密排列，Bank 与 Bank 之间必然存在**间隙**，这些间隙空间构成了无效面积开销。
3. **BIST 测试电路增加**：每个 Bank 需要独立的 BIST 测试接口和控制器，拆分越多，BIST 逻辑的复制开销越大，进一步推升面积。

> **本质原因**：SRAM 的面积并非与容量完全线性缩放，拆分会引入多个重复的"固定开销"（外围电路），这些固定开销的总和随 Bank 数量线性增长，而存储阵列本身的面积却因拆分而碎片化，无法再共享外围资源 [^1]。
>
> **量化认知**：Bank 深度越小，外围电路占该 Bank 总面积的比例越高（小容量 SRAM 的存储阵列面积占比显著低于大容量）。因此拆分越细，总面积增长越偏离线性预期——这正是"过度拆分面积非线性加剧"的根本原因。
>
> **评估方法**：使用 Memory Compiler 对不同 Bank 配置（深度 × 宽度）生成物理模型，直接提取面积、访问时间、功耗数据横向对比，避免凭经验拍板 [^1]。

## 5. 功耗影响

Memory 的功耗包含三项 [^1]：

- **Leakage 功耗**：静态泄漏电流
- **动态读写功耗**：每次访问时的充放电功耗
- **Standby 功耗**：非访问状态下的保持功耗 [^6]

### 5.1 按深度拆分的功耗变化

| 功耗项 | 变化趋势 | 说明 |
|:-------|:--------:|:-----|
| 总 Leakage 功耗 | **↑ 增大** | 总晶体管数增加 [^1] |
| Standby 功耗 | **↑ 增大** | 更多 Bank 需保持准备就绪 [^1] |
| 动态功耗 | **↓ 减小** | 每次仅激活 1 个 Bank [^1] |

### 5.2 低功耗模式运用

合理利用 Memory 的 **SD（关断模式）** 和 **SLP（休眠模式）** 功能，做到动态启用 [^4]：

- **SLP（休眠模式）**：进入低功耗保持状态，降低待命（Standby）功耗 [^6]
- **SD（关断模式）**：直接关断电源，Leakage 和 Standby 均显著下降，**高温下对降低 Leakage 功耗效果尤为明显** [^4]

> **设计要点**：空闲 Bank 应切换至 SLP/SD 状态，需要访问时再唤醒，避免所有 Bank 恒久保持待命；唤醒延迟与功耗收益需在架构层面权衡 [^6]。

## 6. 多 Bank 拆分的收益

| 收益维度 | 说明 |
|:---------|:-----|
| **绕开 IP 限制** | 突破单块 SRAM 的深度/宽度上限，实现大容量存储 [^1] |
| **降低动态功耗** | 每次操作仅激活目标 Bank，无需为整块大阵列供电 [^1] |
| **提升访问带宽** | 不同 Bank 可并行响应互不冲突的访问请求 [^2] |
| **提升工作频率** | 更小的 Bank 尺寸缩短位线长度，减少寄生负载，利于时序收敛 [^1] |

## 7. 过度拆分的风险与代价

### 7.1 拆分数量决策区间

> **说明**：N=2 是收益最大化的推荐折中点；N > 4 表示拆分到 4 份以上时，负面效应开始非线性加剧，属于应避免的过度拆分区间。两者并不矛盾 [^1]。

| Bank 拆分数 | 定性评估 |
|:-----------|:---------|
| N = 1 | 未拆分，受单块 IP 规格限制 |
| **N = 2** | **推荐折中点**：动态功耗收益最大，面积/漏电代价可控 [^1] |
| N = 3 | 收益仍在，代价尚可接受，需量化评估 |
| N = 4 | 收益递减，负面效应开始显现，须以 Memory Compiler 数据决策 |
| N > 4 | **应避免**：负面效应非线性加剧 [^1] |

### 7.2 面积显著增大

拆分越细、面积越大，三个来源（Memory 本身、PR 间隙、BIST 电路）都随 Bank 数线性增长。当 N > 4 时面积增量非线性加剧，小 Bank 的"固定开销"占比远高于大 Bank，总面积显著超出预期 [^1]。

### 7.3 漏电与静态功耗上升

按深度拆分时，总 Leakage 功耗和 Standby 功耗随 Bank 数量线性增长：更多 Bank 意味着更多晶体管处于待机状态；更多 Bank 需保持准备就绪 [^1]。

### 7.4 动态功耗节省边际效益递减

虽然动态功耗随拆分而减小，但当 **N > 2** 后，动态功耗降低趋于饱和，而面积和漏电的代价持续上升，收益快速递减 [^1]。

### 7.5 后端物理实现恶化

- 拆成 4 个或更多 Bank 后，Bank 间间隙增多，绕线资源被碎片化，可能导致拥塞
- 深拆分后 PR 布局的灵活度下降，时序收敛更困难 [^1]

### 7.6 设计复杂度增加

拆分过多后，Bank 选择逻辑、地址译码和数据选择逻辑呈二叉树增长，设计验证复杂度显著上升 [^1]。

### 7.7 小容量 Bank 定制效率低

当 Bank 深度过小（如 < 2K）时，SRAM 相比 Reg Table 没有面积优势，此时强行使用 SRAM 定制反而效率低下，更适合用 Reg Table 实现 [^1]。

> **工程补充**：项目 MEM 定制规则硬性要求单 Bank 容量 ≤ 2K 时采用 Reg Table；实际工程中单 Bank 容量 < 4K 均推荐 Reg Table，小容量 SRAM 的面积效率远不如 Reg Table [^3]。

## 8. 工程实践建议

### 8.1 核心原则

- **拆一半常见但非普适**：动态功耗节省与面积/Leakage 增加的边际效益交叉点通常在 N=2 附近，继续增加 Bank 数则收益递减 [^1]
- **低功耗优化**：合理利用 SD/SLP 实现动态启用，尤其 SD 在高温下对降低 Leakage 效果显著 [^4]
- **同构拆分优先**：优先采用**均匀规格的 Bank**——所有 Bank 深度、宽度、物理尺寸完全一致，即同一款 SRAM IP 实例复制 N 份，便于后端布局布线规整化 [^1][^6]
- **小表用 Reg**：单 Bank 深度 < 2K 时改用 Reg Table 实现 [^1]

### 8.2 推荐设计流程

1. **明确优化目标**：确定 PPA（Performance, Power, Area）三者的优先级排序 [^1]
2. **分析地址访问模式**：判断工作负载特征（顺序 / 随机 / 分区），选择低位交叉 / 高位交叉 / 哈希映射
3. **使用 Memory Compiler 评估**：针对不同 Bank 配置（N=1/2/3/4），生成物理模型进行横向对比 [^1]
4. **量化分析 PPA**：提取面积、访问时间、动态/静态功耗数据 [^1]
5. **架构级仿真验证**：将各配置的时序和冲突模型代入 RTL 仿真，评估实际工作负载下的有效带宽与性能 [^1]
6. **综合决策**：结合优化目标与仿真数据，选定最优配置 [^1]

### 8.3 设计自查清单

- [ ] 是否已明确 PPA 优先级排序？
- [ ] 是否已分析实际工作负载的地址访问模式（顺序 / 随机 / 分区）？
- [ ] 是否已排除宽度拆分方案（除非有端口扩展等特殊需求）？
- [ ] 单 Bank 深度是否 ≥ 2K（否则评估改用 Reg Table）？
- [ ] 所有 Bank 是否采用均匀规格（同构）？
- [ ] 是否已用 Memory Compiler 对 N=2/3/4 配置生成对比数据？
- [ ] 是否已评估 SD/SLP 低功耗模式的引入方案与唤醒延迟代价？
- [ ] 是否已确认 Bank 选择译码逻辑的时序与面积开销可接受？
- [ ] 是否已确认 Bank 拆分后的访问带宽满足性能需求（含并行访问场景）？
