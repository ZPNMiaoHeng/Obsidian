**ai**: 是的，Mermaid 的 `stateDiagram-v2` 要求状态转移的条件字符串**必须用引号包裹**，否则解析器会将其视为未定义的变量或语法错误，导致无法渲染。[^1]

**根本原因**：Mermaid 将冒号后的文本解析为标签（label），只支持三种形式：
1. **不带空格/特殊字符的纯文本**（不推荐）
2. **双引号括起来的字符串**（推荐）
3. **无标签**（省略冒号后的内容）

而 `entry_count == 2K` 包含空格和 `==` 运算符，Mermaid 无法正确解析其含义，必须写成：
```
check_last --> IDLE : "entry_count == 2K"
check_last --> PRE_CLR_VLD : "entry_count < 2K"
```

关于 `2K` 本身：数字加单位（如 `2K`、`3ns`）在 Mermaid 中并不是保留语法，**用引号包裹后完全合法**，渲染时会被当作普通文本显示，不会导致错误。[^2]

**修正后的完整代码**：
```mermaid
stateDiagram-v2
    [*] --> IDLE
    
    state IDLE {
        [*] --> wait_start
        wait_start --> PRE_CLR_VLD : move_start && !pipeline_conflict
    }
    
    state PRE_CLR_VLD {
        [*] --> clr_vld
        clr_vld --> MOVE_READ : vld_clr_done
    }

    state MOVE_READ {
        [*] --> read_sram_tcam
        read_sram_tcam --> MOVE_WRITE_DST : tcam_data_valid && sram_data_valid && !pipeline_conflict
        read_sram_tcam --> RBACK_READ : pipeline_conflict
    }
    
    state RBACK_READ {
        [*] --> hold_data
        hold_data --> read_sram_tcam : !pipeline_conflict
    }
    
    state MOVE_WRITE_DST {
        [*] --> write_dst_data
        write_dst_data --> MOVE_WRITE_MASK : dst_data_done
    }
    
    state MOVE_WRITE_MASK {
        [*] --> write_dst_mask
        write_dst_mask --> MOVE_CLR_SRC : dst_mask_done
    }
    
    state MOVE_CLR_SRC {
        [*] --> clr_src_data
        clr_src_data --> clr_src_mask
        clr_src_mask --> MOVE_VLD_SWITCH : src_clr_done
    }
    
    state MOVE_VLD_SWITCH {
        [*] --> write_dst_vld
        write_dst_vld --> write_clr_src_vld
        write_clr_src_vld --> CHECK_FINISH : vld_switch_done
    }
    
    state CHECK_FINISH {
        [*] --> check_last
        check_last --> IDLE : "entry_count == 2K"
        check_last --> PRE_CLR_VLD : "entry_count < 2K"
    }
```

另外需注意：`RBACK_READ` 到 `MOVE_READ` 的转移，如果是跨复合状态的转移，需要使用带父状态前缀的语法（如 `MOVE_READ.read_sram_tcam`），但如果 `RBACK_READ` 是顶层状态，则直接写 `read_sram_tcam` 即可。你当前版本中第二个代码块（未使用前缀）是正确可用的。
