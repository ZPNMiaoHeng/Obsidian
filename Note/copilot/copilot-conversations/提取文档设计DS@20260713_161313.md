## 提取的设计DS要素

### 1. 方案概述

- **设计思路**：硬件检测 + 软件纠错
- **巡检机制**：硬件定时巡检 TCAM 的 Data 阵列和 Mask 阵列，对每个 entry 进行 ECC 校验
- **错误上报**：根据类型触发不同等级的中断（CE→int0，UE→int2）

### 2. 硬件架构设计

| 组件 | 设计要点 |
|------|----------|
| **巡检 FSM** | IDLE → READ → WAIT → CHECK → GAP → ADDR_INC 循环 |
| **地址生成** | 共用地址计数器 + 阵列选择标志（1-bit sel_arr） |
| **遍历顺序** | Data[0..N-1] → Mask[0..N-1] 循环 |
| **优先级** | ECC 巡检优先级最低，受软件读写、搜索、维护操作反压 |
| **ECC复用** | 直接复用维护读路径上的解码器和写路径上的编码器 |

### 3. 中断与错误记录

- **CE 寄存器组**：记录 Bank、阵列、entry 号、syndrome、错误位位置、累计次数
- **UE 寄存器组**：记录 Bank、阵列、entry 号、syndrome
- **锁存策略**：先到先锁（首个错误被锁存）
- **CE 阈值告警**（可选）：超过可编程阈值触发告警中断

### 4. 寄存器定义（完整）

定义 15 个寄存器：
- 控制类：`PATROL_CTRL`、`PATROL_TIMER`、`PATROL_GAP`
- CE 状态：`ERR_CE_STATUS`、`ERR_CE_BANK`、`ERR_CE_ARR_SEL`、`ERR_CE_ENTRY_ADDR`、`ERR_CE_SYNDROME`、`ERR_CE_BIT_POS`、`ERR_CE_COUNT`
- UE 状态：`ERR_UE_STATUS`、`ERR_UE_BANK`、`ERR_UE_ARR_SEL`、`ERR_UE_ENTRY_ADDR`、`ERR_UE_SYNDROME`

### 5. 软件纠错流程

- **CE 处理**：读错误信息 → 读出完整 entry → 根据 syndrome 和 bit_pos 修正 → 写回 → 清中断
- **UE 处理**：读错误信息 → 定位 → 决定重建或标记无效 → 清中断

### 6. 方案优势

- 中断分级处理
- 错误分类型独立记录
- CE 累计计数监测硬件劣化
- 硬件开销极小（仅 FSM + 地址计数器 + 寄存器）
- 无写冲突风险
