### 三、剩余关键问题

#### P0-1：`move_if_busy` 握手方向仍含二义性

文档原文仍为"输出给 ECC FSM（**或反向检测**）"[^1]。这个"或"是编码前的隐患——若 ECC 写回与搬移 FSM 启动恰好同拍，谁先谁后未定义，可能产生同拍竞态。

**建议**（二选一，必须确定性唯一）：
- **方案一**：ECC 写回请求**打拍寄存**，搬移 FSM 启动前采样 `ecc_write_pending`，发现 pending 则主动让 1 拍；
- **方案二**：搬移 FSM 启动拍检测到 ECC 写回时**主动推迟一拍**。

推荐方案一，采样逻辑更简单，不会引入新的握手状态。

#### P0-2：ECC 写回连续占用可绕过饿死保护（行为 a 的设计漏洞）

行为 (a) 中"反压 1 拍后 grant 软件，实际等效 1 拍"的成立条件是 **ECC 写回稀疏**——若触发当拍及后续 ECC 写回持续到达，软件 grant 会被无限推迟[^2]。多个 1-bit 错误并发（如阵列局部失效、电压跌落）时，饿死保护形同虚设。

> 注意：删除断言只是移除了**验证手段**，不解决**设计问题**。

**建议**（推荐后者，系统性闭环）：
- 给 ECC 写回增加**连续占用上限**（最多连续 N 次后强制让 1 拍）；或
- 行为 (a) 触发当拍**临时屏蔽 ECC 抢占**，保证软件在反压窗口内必然获得 grant。

推荐后者：反压窗口有界 → 软件 grant 有界，与"固定 1 拍"的设计承诺完全一致。

#### P0-3：`move_busy` 与计数器/仲裁的交互未定义（新增）

既然已同意增加 `move_busy`，有三个细节必须编码前明确：

1. **计数器暂停问题**：`move_busy` 期间若计数器继续 +1，阈值可能在搬移期间触发，而行为 (a)/(b) 此时都无法真正 grant 软件（接口被搬移占用），产生"触发但无效"的中间态。**建议：move_busy 期间计数器暂停，move 完成恢复**。
2. **stall 范围扩展**：用户原文只提 stall 软件请求。但 **ECC 巡检读同样在 ARB 内、同样感知不到搬移占用接口**，与 move 存在同样的冲突盲区。**建议：move_busy 广播至 ARB，同时 stall 软件与 ECC 巡检读的 grant**（ECC 写回已由 `move_if_busy` 覆盖）。

#### P1-1：`sw_discard` 缺少 CDC 处理

`sw_discard` 是发给软件源端的物理握手信号，软件通常位于 CPU/慢速总线时钟域。当前文档未提及同步处理[^2]。**建议**：两级同步 + 同步后断言 + 软件重试协议固化为接口规范。

#### P1-2：行为 (b) 的 `SW_STARVED` 死等风险

### 一、验证：论证链完整

ECC 写回不是独立异步请求源，其唯一触发链路为：

```
巡检读（READ_DATA/MASK）→ 检查（CHECK）→ 检测 CE → 写回（WRITE_BACK）[^1]
```

若搬移期间巡检读不发起，则整条链路在源头被阻断，**写回请求不可能产生**，`move_if_busy` 针对写回竞争的握手确实冗余，P0-1 关闭。[^2]

### 二、前提：此论证成立需要实现上的支撑

论证的落实依赖一个已确定的机制——**`move_busy` 期间 ARB 不 grant ECC 巡检读**，即上轮 P0-3 中"move_busy stall ECC 巡检读 grant"的建议。该机制正是 P0-1 关闭的实现基础：

- 巡检读被阻止发起 → 无读-读竞争（巡检读与搬移读的接口竞争也一并消除）；
- 巡检读不发起 → 无新 CE 检测 → 无新写回 → 写回竞争天然不存在。[^3]

**注意**：这并未消除互锁需求，而是将互锁点从"写回"**前移**到"巡检读"。`move_busy` 信号仍然需要，只是作用对象从"stall ECC 写回"变为"暂停 ECC 巡检读"。

### 三、一个需要补齐的边界场景（中间态）

巡检 FSM 若在搬移启动**前一拍**已发出读请求，数据返回与 CE 检测将落在搬移窗口内。此时需明确：

- 已检测出 CE 但尚未执行 `CORRECT_WB_DATA`/`CORRECT_WB_MASK` 的写回请求，**挂起等待搬移完成**后再执行；或
- 搬移 FSM 启动条件增加"ECC FSM 空闲"检查，两者互斥进入。[^4]

建议采用前者（写回挂起），实现更简单。

## 一、请求源

- **流水线查表请求** `pl_search_req`
- **软件请求** `sw_req`：读、写、search TCAM
- **TCAM_ECC_FSM 请求**：
  - 写请求：ECC 1-bit 错误回写正确数据，优先级最高；
  - 读请求：巡检读 TCAM 数据用于 ECC 校验检查，优先级最低

> **说明**：搬移/清除请求**不是独立 ARB 请求源**——由软件寄存器配置触发、独立于 ARB 仲裁。其互斥性由硬件 `move_busy` 互锁 + 软件限制条款双重保障 [^1][^2]。

---

## 二、仲裁优先级

1. **TCAM_ECC_FSM 写请求**，优先级最高（搬移期间经巡检读阻断不产生新写回，见 §七）；
2. **流水线查表请求 vs 软件请求**：
   - 默认流水线查表请求优先级高于软件请求；
   - 内部实现计数器 + 配置寄存器，支持**机会式调度**与**饿死保护**；
3. **TCAM_ECC_FSM 读请求**（巡检），优先级最低。

---

## 三、move_busy 硬件互锁（新增）

搬移/清除不经过 ARB 仲裁，但**物理占用 TCAM 接口**。为降低"可信软件假设"的依赖，增加硬件最终防线：

- 搬移 FSM 输出 **`move_busy`** 广播至 ARB；
- `move_busy` 有效期间，ARB **硬件强制 stall** 以下请求源的 grant：
  - **软件请求**（不依赖软件自觉遵守"搬移期间不下发命令"）；
  - **ECC 巡检读**（从源头阻断 ECC 写回触发链，详见 §七）；
- `move_busy` 期间**计数器暂停**，搬移完成恢复计数（避免"触发但无法 grant"的无效中间态）[^1]。

| 请求源 | 与 move 的协调机制 | 来源 |
|:---|:---|:---:|
| 流水线查表 | `pipeline_conflict`（搬移 FSM 自行避让流水线） | 已有 |
| 软件请求 | `move_busy` stall ARB grant（硬件互锁） | 本轮新增 |
| ECC 巡检读 | `move_busy` stall ARB grant（阻断写回触发链） | 本轮新增 |
| ECC 写回 | 由巡检读阻断天然规避，无需独立握手 | 本轮新增 |

## 四、计数器实现

| 项目 | 设计 |
|:---|:---|
| 信号定义 | **`sw_waiting := sw_req_valid && !sw_grant && !move_busy`**（显式定义，消除实现二义性） |
| 加 1 条件 | `sw_waiting` |
| 清 0 条件 | 软件访问成功（`sw_grant`） |
| 暂停条件 | `move_busy`（搬移期间不计时） |
| 阈值触发 | `cnt >= csr_timeout_timer`（8bit 配置） |
| 饱和行为 | 达到阈值后**不再 +1，保持原值**，直到软件访问成功才清 0；**饱和计数，非回绕计数** |

## 五、行为触发（配置可选，互斥）

配置寄存器：

- `csr_timeout_timer`：8bit 超时阈值；
- `csr_timeout_pressure_pipeline_en`：
  - 1'b1，**行为 (a)**；
  - 1'b0，**行为 (b)**；

### 行为 (a)：反压流水线 1 拍

- 触发条件：`sw_starved && sw_waiting && blocked`（有更高优先级请求占用接口，且软件确实被压制）；
- 反压窗口：**固定 1 拍**（有界，非"直到软件完成"）；
- 反压 1 拍后 grant 软件，软件访问完成（读已确认为 1 拍）；
- **触发当拍临时屏蔽 ECC 写回抢占**：保证"反压 1 拍 → 软件必然 grant"的有界性承诺，不受 ECC 写回连续到达影响（如多个 1-bit 错误并发、阵列局部失效）[^1]；
- 屏蔽逻辑仅在行为 (a) 触发当拍有效，不改变 ECC 写回的最高优先级属性。

### 行为 (b)：软件命令失效

- 触发条件同 (a)；
- 通过 `sw_discard` **物理握手信号**通知源端命令已失效，源端撤销请求（**与 ARB 同时钟域，无需 CDC 处理**）[^3]；
- 置于 `SW_STARVED` 状态：命令失效后计数器**保持阈值不清 0**，重试命令重新触发行为，直到某次访问真正成功才清 0 退出；
- **退出条件**（防止软件永不重试导致死锁）：
  - `!sw_req_valid` 持续 `csr_starved_exit_cycles` 拍后退出 `SW_STARVED`；或
  - 新请求到达时重置等待窗口 [^4]。

```
IDLE ──(cnt 越界 && sw_waiting)──▶ SW_STARVED
SW_STARVED ──(sw_grant)──▶ IDLE          // 访问成功，清计数
SW_STARVED ──(sw_waiting && blocked)──▶ 立即执行行为（a 强占 / b 失效）
SW_STARVED ──(!sw_req_valid 持续 N 拍)──▶ IDLE  // 超时退出，计数器保持
SW_STARVED ──(新请求到达)──▶ 重置等待窗口
```

### 机会式调度（默认路径）

流水线天然存在空拍（包间隙、hash 冲突、后端反压），当 `pl_req == 0` 时直接 grant 软件，**零性能损失**。超时行为仅在流水线持续满负荷超过阈值时触发，反压频率趋近于零 [^5]。

---

## 六、接口协议约束

- **保持协议**：源端 valid 在反压期间**禁止撤销**，必须保持到收到 grant（或 `sw_discard`）；
- **读操作接口占用 1 拍**，数据延迟走输出路径不影响反压窗口，固定 1 拍反压窗口充分；
- 无需 skid buffer——保持协议下在途请求不丢失，仅在源端等待；
- **`sw_discard` 与 ARB 同时钟域**，无需同步器，直接物理连线。

## 七、搬移 FSM 与 ECC 的接口协调（重构）

### 7.1 触发链阻断机制（取代 move_if_busy 握手）

ECC 写回不是独立异步请求源，其唯一触发链路为：

```
巡检读（源头）→ CE 检测 → 写回
```

设计验证结论：**搬移期间 ECC 巡检读不发起，则该链路在源头被阻断，写回请求不可能产生**。[^6]

实现基础：

1. `move_busy` 有效期间，ARB **不 grant ECC 巡检读**（见 §三）；
2. 巡检读被阻止发起 → 无新 CE 检测 → 无新写回 → **写回与搬移的接口竞争天然不存在**；
3. 因此**无需 `move_if_busy` 写回级握手**——互锁点已从"写回"前移至"巡检读"。

### 7.2 在途巡检读边界场景（写回挂起）

巡检 FSM 若在搬移启动**前一拍**已发出读请求，数据返回与 CE 检测会落在搬移窗口内：

- 该巡检读合法，无需规避；
- 若检测出 CE，**写回请求挂起等待 `move_busy` 撤销后再执行**，不抢占搬移接口；
- 实现简单：写回 FSM 增加 `wait !move_busy` 条件，与现有挂起机制天然兼容。

### 7.3 与搬移 FSM 现有机制的关系

| 机制 | 作用 | 状态 |
|:---|:---|:---:|
| `pipeline_conflict` | 搬移 FSM 避让流水线查询 | 已有 |
| `move_busy` stall 软件 grant | 硬件互锁，替代纯软件约束 | 本轮新增 |
| `move_busy` stall 巡检读 grant | 阻断 ECC 写回触发链 | 本轮新增 |
| 写回挂起 | 处理在途巡检读的 CE 结果 | 本轮新增 |

## 八、优先级全景图（两层仲裁机制）

| 优先级 | 请求源 | 仲裁层级 | 与搬移的协调 |
| :-: | :------ | :----- | :--- |
| 1 | ECC 写回 | ARB | 搬移期间经巡检读阻断，不产生新写回；在途结果挂起避让 |
| 2 | 流水线查表 | ARB | 搬移 FSM 通过 `pipeline_conflict` 自行避让 |
| 3 | 搬移操作 | 搬移 FSM 内部（不进 ARB） | — |
| 4 | 软件请求 | ARB（带饿死计数器） | `move_busy` 期间硬件 stall grant |
| 5 | 清除操作 | 搬移 FSM 内部（不进 ARB） | — |
| 6 | ECC 巡检读 | ARB（最低） | `move_busy` 期间硬件 stall grant |

**边界清晰**：ARB 只管流水线/软件/ECC 三类请求源；搬移 FSM 自行管理其 TCAM 接口占用，`move_busy` 广播提供硬件互锁，无需逐请求源独立握手 [^2]。

## 九、寄存器汇总

| 寄存器 | 位宽 | 描述 |
| :--- | :-: | :--- |
| `csr_timeout_timer` | 8 | 饿死保护阈值（建议复位默认非 0，如 `8'hFF`） |
| `csr_timeout_pressure_pipeline_en` | 1 | 1'b1，行为 (a)；1'b0，行为 (b) |
| `csr_starved_exit_cycles` | 8 | 行为 (b) 中 `SW_STARVED` 退出超时阈值（N 拍无请求后退出） |

**计数器特性汇总**：饱和计数（非回绕）；`sw_grant` 清 0；`move_busy` 暂停；阈值态保持原值直到访问成功。
