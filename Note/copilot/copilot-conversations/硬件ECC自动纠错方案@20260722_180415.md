# TCAM ECC 校验实现方案（更新版）

## 1. 概述

本方案遵循 **硬件检测 + 硬件自动纠错 + 回写** 的设计思路。硬件负责后台巡检（Patrol Scrubbing），定期遍历 TCAM 的 Data 阵列和 Mask 阵列，对每个条目进行 ECC 校验。当检测到 **1-bit 错误（CE）** 时，硬件直接纠正数据并写回原地址，无需软件干预，同时上报错误信息供软件记录归档；当检测到 **2-bit 错误（UE）** 时，硬件上报致命中断，由软件介入处理。

TCAM 采用 Data/Mask 独立双阵列架构，每个阵列的每个 entry 作为独立的 ECC 保护域。Data 阵列与 Mask 阵列深度相同，一一对应。

### 中断分级

| 错误类型 | 中断等级 | 说明 |
|:--------:|:--------:|------|
| **1-bit 错误（CE）** | `int0`（普通中断） | 硬件已自动纠正并回写，中断仅用于通知软件记录归档 |
| **2-bit 错误（UE）** | `int2`（致命中断） | 不可纠正错误，需软件立即响应处理 |

## 2. 硬件架构

### 2.1 巡检控制器 FSM

```text
IDLE → READ_DATA → WAIT_DATA → CHECK_DATA → [CORRECT_WB_DATA →] READ_MASK → WAIT_MASK → CHECK_MASK → [CORRECT_WB_MASK →] GAP → ADDR_INC → IDLE/READ_DATA
```

> **状态说明**：
> - `CORRECT_WB_DATA` / `CORRECT_WB_MASK` 为新增状态，仅在检测到 CE 时进入，执行硬件纠错回写。
> - 若检测到 UE，则跳过回写状态，直接触发 `int2` 后继续后续流程。

- **IDLE**：等待 `patrol_enable` 且定时器超时（定时周期可编程）。
- **READ_DATA**：通过维护接口发出读请求，读取 Data 阵列当前 entry 的数据（Data+ECC）。
- **WAIT_DATA**：等待 Data 阵列读数据及 ECC 校验结果（syndrome）。
- **CHECK_DATA**：
  - 无错误 → 直接进入 READ_MASK。
  - **CE（1-bit 错误）** → 锁存错误信息（Bank、Data 阵列、entry 号），硬件校正数据（ECC 解码修正 + 重编码），进入 `CORRECT_WB_DATA`。
  - **UE（2-bit 错误）** → 锁存错误信息（Bank、Data 阵列、entry 号、syndrome），触发 `int2`，进入 READ_MASK（跳过回写）。
- **CORRECT_WB_DATA**：将纠正后的数据通过维护接口写回原 Data 阵列地址，完成后触发 `int0`，进入 READ_MASK。
- **READ_MASK**：通过维护接口发出读请求，读取 Mask 阵列当前 entry 的数据（Mask+ECC）。
- **WAIT_MASK**：等待 Mask 阵列读数据及 ECC 校验结果（syndrome）。
- **CHECK_MASK**：
  - 无错误 → 直接进入 GAP。
  - **CE（1-bit 错误）** → 锁存错误信息（Bank、Mask 阵列、entry 号），硬件校正数据，进入 `CORRECT_WB_MASK`。
  - **UE（2-bit 错误）** → 锁存错误信息（Bank、Mask 阵列、entry 号、syndrome），触发 `int2`，进入 GAP。
- **CORRECT_WB_MASK**：将纠正后的数据写回原 Mask 阵列地址，完成后触发 `int0`，进入 GAP。
- **GAP**：插入可编程的空闲周期（节流控制）。
- **ADDR_INC**：递增 `entry_addr`，跳回 IDLE 或 READ_DATA。

> **设计说明**：对于同一个 index，先完成 Data 阵列校验并可选回写，再完成 Mask 阵列校验并可选回写，然后才更新地址。这种设计确保同一个 entry 的 Data 和 Mask 错误在同一轮巡检中被连续发现并处理。

### 2.2 地址生成与遍历顺序

鉴于 Data 阵列和 Mask 阵列深度相同、一一对应，地址生成器采用以下设计：

- **共用地址计数器**：维护一个 `entry_addr`（0 ~ N-1，N 为每个阵列的 entry 深度）。
- **阵列选择标志**：维护 1-bit `sel_arr`（0=Data，1=Mask），由 FSM 状态隐式控制，无需独立寄存器。
- **遍历顺序**：Data[0] → Mask[0] → Data[1] → Mask[1] → …… → Data[N-1] → Mask[N-1] → 回到 Data[0] 开始下一轮。
- **地址更新机制**：当前 entry 的 Data 和 Mask 均校验并完成回写（如需要）后，`entry_addr` 递增。
- **可配置参数**：
  - 起始/终止地址（支持子区间巡检）。
  - 步长（支持跳过配置，例如每巡检 N 条跳过 M 条）。

### 2.3 优先级与冲突仲裁机制

> **注意**：新方案下，硬件自身会执行回写操作，因此需要新增冲突仲裁机制。

ECC 巡检的优先级在所有访问源中 **最低**，受以下约束：

- **与软件维护访问的冲突**：当软件通过维护接口读写 TCAM 时，巡检的 READ 请求和 CORRECT_WB 写请求均被 **反压**（hold，等待接口释放后重新发出）。软件写优先级高于巡检回写。
- **与搜索操作的冲突**：
  - 巡检 READ：被搜索操作反压。
  - **巡检 CORRECT_WB**：回写操作在 TCAM 内部可能导致搜索逻辑读取到不一致的数据。因此，回写操作将等待搜索操作完成后，在 **下一个空闲周期** 执行。建议 TCAM 接口提供 `search_busy` 信号，巡检控制器检测到该信号有效时，暂停回写操作。
- **与维护操作（valid reset、flush 等）的冲突**：巡检 READ 和 CORRECT_WB 均被反压。
- **反压处理**：通过维护接口的 ready/valid 握手实现。巡检请求发出后，如果接口 busy 或被占用，则暂停当前 FSM 直到接口释放。

### 2.4 ECC 编解码复用

ECC 编解码直接复用 TCAM 维护读路径上的现有 ECC 解码器（用于读校验）和维护写路径上的 ECC 编码器（用于写保护）。巡检读到的数据经过 ECC 解码得到 syndrome 和错误标志位。硬件根据错误标志进行如下操作：

- **CE 场景**：解码器输出校正后的数据，硬件将其锁存，并通过编码器重新编码（生成新的 ECC 校验位），然后通过维护接口写回原地址。
- **UE 场景**：解码器无法校正，硬件锁存原始数据和 syndrome，跳过回写。

### 2.5 中断与错误记录

错误记录采用 **分类型独立寄存器** 设计：

- **CE（1-bit 错误）寄存器组**（记录信息，已自动纠正）：
  - `ERR_CE_BANK`：错误所在 Bank 号。
  - `ERR_CE_ARR_SEL`：错误所在阵列（0=Data，1=Mask）。
  - `ERR_CE_ENTRY_ADDR`：错误 entry 号。
  - `ERR_CE_COUNT`：CE 累计错误次数（软件读清，用于监测硬件劣化趋势）。

- **UE（2-bit 错误）寄存器组**：
  - `ERR_UE_BANK`：错误所在 Bank 号。
  - `ERR_UE_ARR_SEL`：错误所在阵列（0=Data，1=Mask）。
  - `ERR_UE_ENTRY_ADDR`：错误 entry 号。
  - `ERR_UE_SYNDROME`：校正子。

- **中断触发**：
  - `int0`：CE 自动纠正并回写完成后触发，通知软件记录归档软件读清。
  - `int2`：UE 检测到后立即触发软件读清。

- **锁存策略**：硬件采用 **先到先锁** 策略（锁存首个错误信息，后续同类型错误被覆盖）。

- **CE 阈值告警**（可选）：当 `ERR_CE_COUNT` 超过可编程阈值时，可额外触发一次告警中断，提示硬件可能劣化。

> **注**：2-bit 错误（UE）触发 `int2` 致命中断，要求软件立即处理，不存在"累积计数再触发告警"的需求，因此 UE **不配备独立计数器**。CE 则可以通过计数器累积，用于监测硬件劣化趋势。

## 3. 软件处理流程

### 3.1 CE（1-bit 错误）处理流程

1. 中断服务程序（ISR）收到 `int0`，读取 CE 寄存器组获取已自动纠正的错误信息（Bank、阵列、entry 号）。
2. 软件记录错误信息到错误日志，并更新 `ERR_CE_COUNT`。
3. 清除中断标志，继续正常运行（无需执行任何数据修正操作）。

> **注意**：硬件已确保数据已正确写回，软件仅需记录归档和监测硬件劣化趋势。

### 3.2 UE（2-bit 错误）处理流程

1. 中断服务程序（ISR）收到 `int2`，读取 UE 寄存器组确认错误信息。
2. 根据 `ERR_UE_BANK`、`ERR_UE_ARR_SEL` 和 `ERR_UE_ENTRY_ADDR` 定位错误位置。
3. 软件评估该条目的重要性，决定处理策略：
   - 若可重建 → 删除原条目，重新下发。
   - 若不可重建 → 标记该条目为无效，记录错误日志。
4. 清除中断标志，恢复巡检。

> **注意**：若同一个 entry 的 Data 和 Mask 均有错误，硬件会各自独立处理或上报。UE 处理期间，软件应优先保证 `int2` 的中断响应延迟最小化。

## 4. 节流与定时控制

- **定时启动**：`PATROL_TIMER` 寄存器配置巡检启动间隔（以时钟周期为单位），超时后巡检自动开始一轮扫描。
- **空闲间隙**：`GAP_CYCLES` 寄存器保留，默认值为 0。由于巡检优先级最低，软件/搜索访问时会被自动反压，因此 TCAM 空闲时巡检可全速运行。仅在调试或功耗受限场景下，软件可将其配置为非零值以降低巡检速率。
- **反压计数**：可选的 `BACKPRESSURE_CNT` 寄存器记录被反压的次数，供软件评估巡检效率。

## 5. 关键设计考虑

### 5.1 Data/Mask 独立校验与回写

由于 Data 和 Mask 是独立的 SRAM 阵列，分别具有独立的 ECC 校验位，因此巡检必须分别遍历两个阵列。当检测到 CE 时，硬件分别对每个阵列独立执行纠错回写操作。每个 entry 的 ECC 域仅包含该阵列的存储位，不跨阵列。

### 5.2 写冲突的避免

- **硬件回写 vs. 搜索**：新方案引入了硬件回写操作。回写需要遵循 TCAM 写时序，并且可能与搜索操作冲突。设计需提供冲突仲裁机制：回写操作在 TCAM 处于搜索状态时被暂停，直到搜索完成后的下一个空闲周期执行。
- **硬件回写 vs. 软件维护写**：软件写优先级高于巡检回写，巡检回写会被反压。软件应尽量减少在巡检过程中的写操作，以避免巡检效率下降。
- **硬件回写 vs. 自身巡检读**：回写和读数操作不能同时对同一阵列进行。FSM 已通过状态顺序（READ→CHECK→CORRECT_WB）天然避免了此类冲突。

### 5.3 错误窗口

- **CE 场景**：硬件自动纠错回写，错误窗口极小（从检测到回写完成通常仅需数个时钟周期）。在此期间，该条目被搜索命中时可能输出错误数据，但窗口极短，风险极低。
- **UE 场景**：软件响应时间必须控制在系统容错范围内。建议将 `int2`（UE）的中断优先级设置为最高，确保快速响应。

## 6. 寄存器定义

| 寄存器名称 | 偏移 | 功能 |
|-----------|:----:|------|
| `PATROL_CTRL` | 0x00 | 巡检使能、起始/终止地址、步长配置 |
| `PATROL_TIMER` | 0x04 | 巡检启动间隔（周期数） |
| `PATROL_GAP` | 0x08 | 巡检间的空闲周期数，默认 0x0 |
| `ERR_CE_STATUS` | 0x10 | CE 错误状态标志，读清 |
| `ERR_CE_BANK` | 0x14 | CE 错误 Bank 号 |
| `ERR_CE_ARR_SEL` | 0x18 | CE 错误所在阵列（0=Data，1=Mask） |
| `ERR_CE_ENTRY_ADDR` | 0x1C | CE 错误 entry 号 |
| `ERR_CE_COUNT` | 0x28 | CE 累计错误次数，软件读清 |
| `ERR_UE_STATUS` | 0x30 | UE 错误状态标志，读清 |
| `ERR_UE_BANK` | 0x34 | UE 错误 Bank 号 |
| `ERR_UE_ARR_SEL` | 0x38 | UE 错误所在阵列（0=Data，1=Mask） |
| `ERR_UE_ENTRY_ADDR` | 0x3C | UE 错误 entry 号 |
| `ERR_UE_SYNDROME` | 0x40 | UE 校正子 |

> **变更说明**：CE 寄存器组移除了 `ERR_CE_SYNDROME` 和 `ERR_CE_BIT_POS`（硬件已完成纠正），保留用于记录和监控的 `ERR_CE_BANK`、`ERR_CE_ARR_SEL`、`ERR_CE_ENTRY_ADDR`。

## 7. 方案优势

- **中断分级处理**：CE 使用 `int0` 普通中断（通知性），UE 使用 `int2` 致命中断，便于软件区分处理优先级。
- **CE 自动纠错**：1-bit 错误由硬件直接纠正并回写，无需软件干预，响应速度快，错误窗口极短。
- **错误分类型独立记录**：CE 与 UE 使用独立的寄存器组，CE 寄存器已精简。
- **CE 计数功能**：CE 累计计数器用于监测硬件劣化趋势；UE 无需计数，触发即立即处理。
- **信息上报完整**：CE 上报 Bank、阵列、entry 号；UE 上报 Bank、阵列、entry 号和 syndrome。
- **逐 entry 连续校验**：同一 entry 的 Data 和 Mask 连续校验完成，便于处理。
- **硬件开销较小**：仅需巡检 FSM、共用地址计数器、1-bit 阵列选择、中断寄存器及回写逻辑。
- **全速巡检**：GAP 默认 0，TCAM 空闲时巡检全速运行，最大限度地缩小错误发现窗口。
