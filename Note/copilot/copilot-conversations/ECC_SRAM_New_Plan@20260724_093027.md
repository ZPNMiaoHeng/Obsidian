# TCAM ECC 校验方案（更新 v2.0）

## 1. 概述

本方案遵循 **硬件检测 + 硬件自动纠错** 的设计思路 [^1]。硬件负责后台巡检（Patrol Scrubbing），定期遍历 TCAM 的 Data 阵列和 Mask 阵列。当检测到 **1-bit 可纠正错误（CE）** 时，硬件自动执行纠错并写回原地址，无需软件干预。当检测到 **2-bit 不可纠正错误（UE）** 时，上报致命中断并由软件介入处理。

### 核心变更

- **ECC 校验位存储**：在 IP 外部集成一个带写掩码（Bit-Write Mask）的独立 SRAM，用于存储 Data 和 Mask 阵列的 ECC 校验位。该 SRAM 本身不额外做 ECC 校验 [^1]。
- **独立校验**：Data 与 Mask 阵列仍分别独立计算 ECC 校验位 [^2]，但校验位**统一**存储在上述外部 SRAM 中。
- **硬件自动回写**：1-bit 错误由硬件检测到后立即自动纠正并写回阵列 [^3]。回写优先级最高，可反压正常流水线访问。

### 中断分级

| 错误类型 | 中断等级 | 说明 |
|:--------:|:--------:|------|
| **1-bit 错误（CE）** | `int0`（信息性中断） | 硬件已自动纠正并回写，仅供软件记录归档 |
| **2-bit 错误（UE）** | `int2`（致命中断） | 不可纠正错误，需软件立即响应处理 |

## 2. 硬件架构

### 2.1 存储子系统

#### 2.1.1 ECC 校验位 SRAM

在 IP 外部实例化一个独立的 **带写掩码的 SRAM**，其规格如下：

| 参数 | 说明 |
|:----|:----|
| **深度** | 与 TCAM Data/Mask 阵列深度相同 |
| **宽度** | 由 Data 和 Mask 阵列的 ECC 校验位宽度之和决定（`ECC_WIDTH_DATA + ECC_WIDTH_MASK`） |
| **写掩码** | 支持字节/位级写掩码，用于回写时只修改指定阵列的校验位 |
| **ECC 保护** | 该 SRAM **不额外做 ECC 校验** [^1] |

#### 2.1.2 地址映射

- **Data 阵列与 Mask 阵列的 ECC 校验位共享同一个外部 SRAM 的地址空间**。
- 对于同一 entry，其 Data 和 Mask 阵列的校验位分别存储在 SRAM 地址的低位和高位（由硬件内部拼接）。
- 写入时，通过 SRAM 的写掩码功能，保证对 Data 或 Mask 的写入只影响对应的校验位区域。

### 2.2 巡检控制器 FSM

```
IDLE → READ_DATA → CHECK_DATA → READ_MASK → CHECK_MASK → GAP → ADDR_INC → IDLE/READ_DATA
       ↓ (CE)            ↓ (CE)
    [WRITE_BACK]      [WRITE_BACK]
```

- **IDLE**：等待 `patrol_enable` 且定时器超时（定时周期可编程）。
- **READ_DATA**：通过维护接口发出读请求，读取 Data 阵列当前 entry 的数据，同时从外部 SRAM 读入其对应的 ECC 校验位。
- **CHECK_DATA**：
  - 无错误 → 直接进入 READ_MASK。
  - **CE（1-bit 错误）** → 进入 **WRITE_BACK_DATA** 状态，同时锁存错误信息（Bank、Data 阵列、entry 号、syndrome）用于上报。
  - **UE（2-bit 错误）** → 锁存错误信息，触发 `int2`，进入 READ_MASK。
- **WRITE_BACK_DATA**：将**纠正后的数据**与**新的 ECC 校验位**写回原地址。写回操作通过外部 SRAM 的写掩码接口进行，只更新 Data 阵列对应的校验位部分。完成后返回 READ_MASK。
- **READ_MASK**：通过维护接口发出读请求，读取 Mask 阵列当前 entry 的数据及其对应的 ECC 校验位。
- **CHECK_MASK**：
  - 无错误 → 直接进入 GAP。
  - **CE（1-bit 错误）** → 进入 **WRITE_BACK_MASK** 状态，同时锁存错误信息。
  - **UE（2-bit 错误）** → 锁存错误信息，触发 `int2`，进入 GAP。
- **WRITE_BACK_MASK**：将纠正后的数据与新的 ECC 校验位写回原地址，只更新 Mask 阵列对应的校验位部分。完成后进入 GAP。
- **GAP**：插入可编程的空闲周期（节流控制）。
- **ADDR_INC**：递增 `entry_addr`，跳回 IDLE 或 READ_DATA。

### 2.3 优先级与反压机制

#### 2.3.1 硬件回写优先级

- ECC 硬件的回写操作（`WRITE_BACK_DATA` / `WRITE_BACK_MASK`）在所有访问源中 **优先级最高** [^1]。
- 当硬件检测到 CE 并需要回写时，如果回写地址与当前流水线的读/写/搜索操作发生冲突，硬件 **反压流水线**（拉低 `ready` 信号），待回写完成后释放 [^1]。
- 考虑到 1-bit 错误发生概率极低，由此引起的性能损失是可接受的 [^1]。

#### 2.3.2 巡检读优先级

- 巡检过程中的读操作（`READ_DATA` / `READ_MASK`）优先级依然 **最低** [^4]。
- 当软件或搜索访问 TCAM 时，巡检读请求被反压，待接口空闲后重新发出。

### 2.4 ECC 编解码与外部 SRAM 交互

- **读路径**：
  1. 从 TCAM 阵列读出数据（Data/Mask）。
  2. 从外部 SRAM 读出对应的 ECC 校验位。
  3. 数据与校验位送入 ECC 解码器，生成 syndrome 和错误标志。
- **写路径（回写）**：
  1. ECC 解码器纠正后的数据与原始数据一起，送入 ECC 编码器计算新的校验位。
  2. 纠正后的数据写回 TCAM 阵列。
  3. 新的校验位通过外部 SRAM 的**写掩码接口**，只更新对应阵列的校验位区域。

### 2.5 中断与错误记录

- **中断触发**：
  - **CE**：硬件自动回写完成后，可选地触发 `int0`（信息性中断），通知软件记录错误事件。此中断不会阻塞硬件后续操作。
  - **UE**：检测到后立即触发 `int2`，软件需立刻响应。
- **寄存器设计**：
  - 错误记录寄存器组（包括 Bank、阵列、entry 号、syndrome）保留，用于软件读取归档。
  - 新增 `ERR_CE_AUTO_CORRECTED` 状态位，指示 CE 已由硬件自动处理。

## 3. 软件纠错流程

### 3.1 CE（1-bit 错误）处理

1. （可选）中断服务程序（ISR）收到 `int0`，读取 CE 寄存器组确认错误信息。
2. 软件将错误信息（Bank、阵列、entry 号、syndrome、发生时间等）记录到日志。
3. 清除中断标志。
4. **无需软件执行纠错写回**，硬件已完成 [^3]。

### 3.2 UE（2-bit 错误）处理

1. 中断服务程序（ISR）收到 `int2`，读取 UE 寄存器组确认错误信息。
2. 根据 `ERR_UE_BANK`、`ERR_UE_ARR_SEL` 和 `ERR_UE_ENTRY_ADDR` 定位错误位置。
3. 软件评估该条目的重要性，决定处理策略：
   - 若可重建 → 删除原条目，重新下发。
   - 若不可重建 → 标记该条目为无效，记录错误日志。
4. 清除中断标志，恢复巡检。

## 4. 关键设计考虑

### 4.1 外部 SRAM 的写掩码

- 外部 SRAM 必须支持**带写掩码的写入** [^1]。
- 在设计 ECC Wrapper 时，需将 TCAM 阵列的写使能信号与 SRAM 的写掩码信号关联，确保只更新发生错误的阵列（Data/Mask）的校验位，不影响另一个。
- 硬件回写时，需要根据 `CHECK_DATA` 或 `CHECK_MASK` 的判定结果，使能对应的写掩码位。

### 4.2 回写操作的原子性

- 从检测到 CE 到完成回写，是一个不可中断的原子操作。
- 在 `WRITE_BACK_DATA` 或 `WRITE_BACK_MASK` 状态下，FSM 不应响应任何新的反压或中断请求。

### 4.3 数据一致性问题

- 当流水线访问正在进行时发生 CE，硬件回写可能修改正被访问的条目数据。由于反压机制，流水线在当前条目处理完成后才会暂停，确保数据一致性。
- 搜索操作中（`compare` 期间）发生的 CE，硬件回写不会影响当前搜索的 HITLINE 结果（因为搜索路径是组合逻辑，而 ECC 纠错发生在回写阶段）。

### 2.3 地址生成与遍历顺序

鉴于 Data 阵列和 Mask 阵列深度相同、一一对应，地址生成器采用以下设计：

- **共用地址计数器**：维护一个 `entry_addr`（0 ~ N-1，N 为每个阵列的 entry 深度）。
- **阵列选择标志**：维护 1-bit `sel_arr`（0=Data，1=Mask），由 FSM 状态隐式控制，无需独立寄存器。
- **遍历顺序**：Data[0] → Mask[0] → Data[1] → Mask[1] → …… → Data[N-1] → Mask[N-1] → 回到 Data[0] 开始下一轮。
- **地址更新机制**：当前 entry 的 Data 和 Mask 均校验完成后（即 CHECK_MASK 状态结束后），`entry_addr` 递增。
- **可配置参数**：
  - 起始/终止地址（支持子区间巡检）。
  - 步长（支持跳过配置，例如每巡检 N 条跳过 M 条）。

#### 2.4.1 硬件回写优先级

- ECC 硬件的回写操作（`WRITE_BACK_DATA` / `WRITE_BACK_MASK`）在所有访问源中 **优先级最高** [^1]。

- 考虑到 1-bit 错误发生概率极低，由此引起的性能损失是可接受的 [^1]。

#### 2.4.2 巡检读优先级

- 巡检过程中的读操作（`READ_DATA` / `READ_MASK`）优先级 **最低**，受以下约束：
  - 当软件通过维护接口读写 TCAM 时，巡检 READ 请求被 **反压**（hold，等待接口释放后重新发出）。
  - 当 TCAM 正在进行搜索操作时，巡检 READ 同样被反压。
  - 当 TCAM 正在进行 valid reset、flush 等维护操作时，巡检 READ 被反压。
- 巡检控制器在 IDLE 状态下持续检测维护接口的忙状态，仅当接口空闲时才启动 READ。

### 2.5 ECC 编解码与外部 SRAM 交互

- **读路径**：
  1. 从 TCAM 阵列读出数据（Data/Mask）。
  2. 从外部 SRAM 读出对应的 ECC 校验位。
  3. 数据与校验位送入 ECC 解码器，生成 syndrome 和错误标志。
- **写路径（回写）**：
  1. ECC 解码器纠正后的数据与原始数据一起，送入 ECC 编码器计算新的校验位。
  2. 纠正后的数据写回 TCAM 阵列。
  3. 新的校验位通过外部 SRAM 的**写掩码接口**，只更新对应阵列的校验位区域。

### 2.6 中断与错误记录

错误记录采用 **分类型独立寄存器** 设计：

- **CE（1-bit 错误）寄存器组**：
  - `ERR_CE_BANK`：错误所在 Bank 号。
  - `ERR_CE_ARR_SEL`：错误所在阵列（0=Data，1=Mask）。
  - `ERR_CE_ENTRY_ADDR`：错误 entry 号。
  - `ERR_CE_SYNDROME`：校正子。
  - `ERR_CE_COUNT`：CE 累计错误次数（软件读清，用于监测硬件劣化趋势）。
  - `ERR_CE_AUTO_CORRECTED`：状态位，指示 CE 已由硬件自动处理。

- **UE（2-bit 错误）寄存器组**：
  - `ERR_UE_BANK`：错误所在 Bank 号。
  - `ERR_UE_ARR_SEL`：错误所在阵列（0=Data，1=Mask）。
  - `ERR_UE_ENTRY_ADDR`：错误 entry 号。
  - `ERR_UE_SYNDROME`：校正子。

- **中断触发**：
  - `int0`：CE 硬件回写完成后触发，仅供软件记录归档。
  - `int2`：UE 检测到后立即触发，软件需立刻响应。

- **锁存策略**：硬件采用 **先到先锁** 策略（锁存首个错误信息，后续错误被覆盖）。

- **CE 阈值告警**（可选）：当 `ERR_CE_COUNT` 超过可编程阈值时，可额外触发一次告警中断，提示硬件可能劣化。

### 2.7 校正子（Syndrome）与错误位位置（Bit Position）的关系

校正子（Syndrome）是 ECC 解码过程中产生的中间计算结果，等于新校验位与存储校验位的异或值。对于 SEC-DED 码，校正子非零时指示存在错误。硬件不再需要 `ERR_CE_BIT_POS` 寄存器——因为纠错由硬件自动完成，软件无需定位错误位。但 Syndrome 信息仍然保留，供软件记录归档。

## 3. 软件纠错流程

### 3.1 CE（1-bit 错误）处理

1. （可选）中断服务程序（ISR）收到 `int0`，读取 CE 寄存器组确认错误信息。
2. 软件将错误信息（Bank、阵列、entry 号、syndrome、发生时间等）记录到日志。
3. 清除中断标志。
4. **无需软件执行纠错写回**，硬件已完成 [^1]。

### 3.2 UE（2-bit 错误）处理

1. 中断服务程序（ISR）收到 `int2`，读取 UE 寄存器组确认错误信息。
2. 根据 `ERR_UE_BANK`、`ERR_UE_ARR_SEL` 和 `ERR_UE_ENTRY_ADDR` 定位错误位置。
3. 软件评估该条目的重要性，决定处理策略：
   - 若可重建 → 删除原条目，重新下发。
   - 若不可重建 → 标记该条目为无效，记录错误日志。
4. 清除中断标志，恢复巡检。

> **注意**：若同一个 entry 的 Data 和 Mask 均有错误，软件可在一次读操作中同时修正，分别写回。UE 处理期间，软件应优先保证 `int2` 的中断响应延迟最小化。

## 4. 节流与定时控制

- **定时启动**：`PATROL_TIMER` 寄存器配置巡检启动间隔（以时钟周期为单位），超时后巡检自动开始一轮扫描。
- **全速运行**：删除了 `GAP_CYCLES` 寄存器，巡检在 TCAM 空闲时全速连续运行 [^2]。
- **反压计数**：可选的 `BACKPRESSURE_CNT` 寄存器记录被反压的次数，供软件评估巡检效率。

## 5. 关键设计考虑

### 5.1 Data/Mask 独立校验

由于 Data 和 Mask 是独立的 SRAM 阵列，分别具有独立的 ECC 校验位，因此巡检必须分别遍历两个阵列。每个 entry 的 ECC 域仅包含该阵列的存储位，不跨阵列。

### 5.2 回写原子性与写冲突

从检测到 CE 到完成回写，是一个不可中断的原子操作。硬件回写优先级最高，可反压流水线，确保回写操作的原子性 [^1]。

### 5.3 错误窗口

- **CE 场景**：硬件检测到 CE 后立即执行自动回写，错误窗口极小（仅数周期级），远小于软件纠错的毫秒级窗口。
- **UE 场景**：软件响应时间必须控制在系统容错范围内。建议将 `int2`（UE）的中断优先级设置为最高，确保快速响应。

### 5.4 外部 SRAM 的写掩码

外部 SRAM 必须支持**带写掩码的写入**。在设计 ECC Wrapper 时，需将 TCAM 阵列的写使能信号与 SRAM 的写掩码信号关联，确保只更新发生错误的阵列（Data/Mask）的校验位，不影响另一个。

## 7. 方案优势

- **中断分级处理**：CE 使用 `int0` 信息性中断，UE 使用 `int2` 致命中断，便于软件区分处理优先级。
- **硬件自动回写**：CE 由硬件自动纠正并回写，消除软件纠错延迟，极大缩小错误窗口 [^1]。
- **反压性能可控**：回写反压产生概率极低，性能损失可接受 [^1]。
- **错误分类型独立记录**：CE 与 UE 使用独立的寄存器组，避免不同类型错误相互覆盖。
- **CE 计数功能**：CE 累计计数器用于监测硬件劣化趋势。
- **逐 entry 连续校验**：同一 entry 的 Data 和 Mask 连续校验完成，便于软件一次性处理两个阵列的错误。
- **全速巡检**：删除 GAP 状态，TCAM 空闲时巡检全速运行，最大限度地缩小错误发现窗口 [^2]。

## 两种机制的对比

### 您描述的方案：计数翻转触发单次读

```
计数器计数 → 翻转 → 读一次 Data → 读一次 Mask → 完成 → 重新计数 → ...
```

- **触发方式**：计数器溢出/翻转作为**触发事件**，事件发生后执行一次完整的读操作（Data + Mask）。
- **遍历行为**：每次触发只读**当前计数值对应的一个 entry**，完成后停止，等待下一次计数翻转。
- **本质上**：这是一种**事件驱动的单次检查**，而非连续遍历。

### 之前讨论的方案：定时巡检（Patrol Scrubbing）

```
IDLE → [定时器超时] → READ_DATA[0] → CHECK → READ_MASK[0] → CHECK → ADDR_INC[1] → READ_DATA[1] → ... → 遍历完所有 entry → IDLE
```

- **触发方式**：定时器超时后启动**一轮完整的扫描**。
- **遍历行为**：一轮扫描中连续遍历**所有 entry**（0 → 1 → 2 → ... → N-1），完成后回到 IDLE 等待下一次定时器超时。
- **本质上**：这是一种**周期性的全遍历扫描**。

---

## 关键区别总结

| 维度 | 计数翻转触发的单次读 | 定时巡检（Patrol Scrubbing） |
|:----|:------------------:|:--------------------------:|
| **触发条件** | 计数器翻转（事件驱动） | 定时器超时（周期性） |
| **每次触发处理量** | 仅 1 个 entry | **全部 entry（0~N-1）** |
| **遍历顺序** | 地址由计数器值决定 | FSM 内部地址计数器递增 |
| **是否保证全覆盖** | **否**（取决于计数范围与翻转频率） | **是**（一轮扫描覆盖所有） |
| **发现错误的时效性** | 取决于计数器翻转频率 | 取决于巡检周期 |
| **典型用途** | 调试、抽检、低功耗背景检查 | 标准的 ECC 巡检保护 |

**适用场景**：
- 系统**对可靠性要求不高**，仅需要定期抽检
- **功耗极度敏感**，无法承受全遍历的功耗开销
- 调试阶段用于定点触发某个特定地址的检查
- 与正常操作紧密耦合，利用空闲时隙单次检查

**适用场景**：
- 系统**对可靠性要求较高**，需要保证所有 entry 被定期覆盖

# TCAM ECC 校验方案（更新 v2.2）

## 1. 概述

本方案遵循 **硬件检测 + 硬件自动纠错** 的设计思路。硬件通过计数翻转触发机制进行后台巡检：计数器计数到设定值后翻转，触发一次读操作，读取当前地址对应的一个 entry（Data + Mask），完成后地址递增，重新开始计数。当检测到 **1-bit 可纠正错误（CE）** 时，硬件自动执行纠错并写回原地址，无需软件干预。当检测到 **2-bit 不可纠正错误（UE）** 时，上报致命中断并由软件介入处理。

### 核心方案变更

- **ECC 校验位存储**：在 IP 外部集成一个带写掩码（Bit-Write Mask）的独立 SRAM，用于存储 Data 和 Mask 阵列的 ECC 校验位。该 SRAM 本身不额外做 ECC 校验 [^1]。
- **独立校验、统一存储**：Data 与 Mask 阵列分别独立计算 ECC 校验位，但校验位**统一**存储在上述外部 SRAM 中 [^1]。
- **硬件自动回写**：1-bit 错误由硬件检测到后立即自动纠正并写回阵列。回写优先级最高，可反压正常流水线访问 [^1]。
- **计数翻转触发**：计数器周期性地触发单次读操作，每次处理一个 entry，地址递增覆盖全部条目 [^2]。

### 中断分级

| 错误类型 | 中断等级 | 说明 |
|:--------:|:--------:|------|
| **1-bit 错误（CE）** | `int0`（信息性中断） | 硬件已自动纠正并回写，仅供软件记录归档 |
| **2-bit 错误（UE）** | `int2`（致命中断） | 不可纠正错误，需软件立即响应处理 |

## 2. 硬件架构

### 2.1 存储子系统

#### 2.1.1 ECC 校验位 SRAM

在 IP 外部实例化一个独立的 **带写掩码的 SRAM**，其规格如下：

| 参数 | 说明 |
|:----|:------|
| **深度** | 与 TCAM Data/Mask 阵列深度相同 |
| **宽度** | 由 Data 和 Mask 阵列的 ECC 校验位宽度之和决定（`ECC_WIDTH_DATA + ECC_WIDTH_MASK`） |
| **写掩码** | 支持字节/位级写掩码，用于回写时只修改指定阵列的校验位 |
| **ECC 保护** | 该 SRAM **不额外做 ECC 校验** [^1] |

#### 2.1.2 地址映射

- Data 阵列与 Mask 阵列的 ECC 校验位共享同一个外部 SRAM 的地址空间。
- 对于同一 entry，其 Data 和 Mask 阵列的校验位分别存储在 SRAM 地址的低位和高位（由硬件内部拼接）。
- 写入时，通过 SRAM 的写掩码功能，保证对 Data 或 Mask 的写入只影响对应的校验位区域。

### 2.2 巡检控制器 FSM

```
IDLE → [计数器翻转] → READ_DATA → CHECK_DATA → READ_MASK → CHECK_MASK → ADDR_INC → IDLE
                        ↓ (CE)            ↓ (CE)
                     [WRITE_BACK]      [WRITE_BACK]
```

- **IDLE**：等待计数器翻转（计数器持续计数时钟周期）。
- **计数器翻转**：计数器达到预设值 `PATROL_INTERVAL` 后翻转，触发一次巡检操作。
- **READ_DATA**：通过维护接口发出读请求，读取当前 `entry_addr` 指向的 Data 阵列数据，同时从外部 SRAM 读入其对应的 ECC 校验位。
- **CHECK_DATA**：
  - 无错误 → 直接进入 READ_MASK。
  - **CE（1-bit 错误）** → 进入 **WRITE_BACK_DATA** 状态，同时锁存错误信息。
  - **UE（2-bit 错误）** → 锁存错误信息，触发 `int2`，进入 READ_MASK。
- **WRITE_BACK_DATA**：将纠正后的数据与新的 ECC 校验位写回原地址。写回操作通过外部 SRAM 的写掩码接口进行，只更新 Data 阵列对应的校验位部分。完成后进入 READ_MASK。
- **READ_MASK**：通过维护接口发出读请求，读取当前 `entry_addr` 指向的 Mask 阵列数据及其对应的 ECC 校验位。
- **CHECK_MASK**：
  - 无错误 → 直接进入 ADDR_INC。
  - **CE（1-bit 错误）** → 进入 **WRITE_BACK_MASK** 状态，同时锁存错误信息。
  - **UE（2-bit 错误）** → 锁存错误信息，触发 `int2`，进入 ADDR_INC。
- **WRITE_BACK_MASK**：将纠正后的数据与新的 ECC 校验位写回原地址，只更新 Mask 阵列对应的校验位部分。完成后进入 ADDR_INC。
- **ADDR_INC**：递增 `entry_addr`（当 `entry_addr` 达到最大值后回绕至 0），复位计数器，跳回 IDLE 等待下一次翻转 [^2]。

**设计说明**：每次计数翻转触发一次完整的读操作（先读 Data 阵列再读 Mask 阵列），完成后地址递增并重新计数。地址依次遍历 0 ~ N-1，循环覆盖所有 entry，不存在检查盲区 [^3]。

### 2.3 地址生成与遍历顺序

- **共用地址计数器**：维护一个 `entry_addr`（0 ~ N-1，N 为每个阵列的 entry 深度），每次完成一次 Data + Mask 读操作后递增 1。
- **遍历顺序**：Data[t] → Mask[t] → Data[t+1] → Mask[t+1] → ... → Data[N-1] → Mask[N-1] → Data[0] → Mask[0] → ...，循环往复。
- **地址回绕**：当 `entry_addr` 递增超过 N-1 时，回绕至 0。
- **可配置参数**：
  - 起始/终止地址（支持子区间巡检）。
  - 步长（支持跳过配置，例如每巡检 N 条跳过 M 条）。

### 2.4 优先级与反压机制

#### 2.4.1 硬件回写优先级

- ECC 硬件的回写操作（`WRITE_BACK_DATA` / `WRITE_BACK_MASK`）在所有访问源中 **优先级最高** [^1]。
- 当硬件检测到 CE 并需要回写时，如果回写地址与当前流水线的读/写/搜索操作发生冲突，硬件 **反压流水线**（拉低 `ready` 信号），待回写完成后释放 [^1]。
- 考虑到 1-bit 错误发生概率极低，由此引起的性能损失是可接受的 [^1]。

#### 2.4.2 巡检读优先级

- 巡检过程中的读操作（`READ_DATA` / `READ_MASK`）优先级 **最低**，受以下约束：
  - 当软件通过维护接口读写 TCAM 时，巡检 READ 请求被 **反压**（hold，等待接口释放后重新发出）。
  - 当 TCAM 正在进行搜索操作时，巡检 READ 同样被反压。
  - 当 TCAM 正在进行 valid reset、flush 等维护操作时，巡检 READ 被反压。
- 巡检控制器在 IDLE 状态下持续检测维护接口的忙状态，仅当接口空闲时才启动 READ。

### 2.5 ECC 编解码与外部 SRAM 交互

- **读路径**：
  1. 从 TCAM 阵列读出数据（Data/Mask）。
  2. 从外部 SRAM 读出对应的 ECC 校验位。
  3. 数据与校验位送入 ECC 解码器，生成 syndrome 和错误标志。
- **写路径（回写）**：
  1. ECC 解码器纠正后的数据与原始数据一起，送入 ECC 编码器计算新的校验位。
  2. 纠正后的数据写回 TCAM 阵列。
  3. 新的校验位通过外部 SRAM 的**写掩码接口**，只更新对应阵列的校验位区域。

### 2.6 中断与错误记录

错误记录采用 **分类型独立寄存器** 设计：

- **CE（1-bit 错误）寄存器组**：
  - `ERR_CE_BANK`：错误所在 Bank 号。
  - `ERR_CE_ARR_SEL`：错误所在阵列（0=Data，1=Mask）。
  - `ERR_CE_ENTRY_ADDR`：错误 entry 号。
  - `ERR_CE_SYNDROME`：校正子（保留用于诊断分析 [^4]）。
  - `ERR_CE_COUNT`：CE 累计错误次数（软件读清，用于监测硬件劣化趋势）。
  - `ERR_CE_AUTO_CORRECTED`：状态位，指示 CE 已由硬件自动处理。

- **UE（2-bit 错误）寄存器组**：
  - `ERR_UE_BANK`：错误所在 Bank 号。
  - `ERR_UE_ARR_SEL`：错误所在阵列（0=Data，1=Mask）。
  - `ERR_UE_ENTRY_ADDR`：错误 entry 号。
  - `ERR_UE_SYNDROME`：校正子（保留用于区分 UE 类型 [^4]）。

- **中断触发**：
  - `int0`：CE 硬件回写完成后触发，仅供软件记录归档。
  - `int2`：UE 检测到后立即触发，软件需立刻响应。

- **锁存策略**：硬件采用 **先到先锁** 策略（锁存首个错误信息，后续错误被覆盖）。

- **CE 阈值告警**（可选）：当 `ERR_CE_COUNT` 超过可编程阈值时，可额外触发一次告警中断，提示硬件可能劣化。

### 2.7 校正子（Syndrome）的用途

虽然 CE 已被硬件自动纠正，UE 无法定位具体错误位，但保留 `ERR_CE_SYNDROME` 和 `ERR_UE_SYNDROME` 仍有以下价值 [^4]：

- **故障诊断**：通过 syndrome 模式可判断错误是否为固定位错误（如某条位线短路），辅助定位硬件缺陷。
- **劣化趋势分析**：统计不同 syndrome 值的分布，区分随机软错误 vs. 系统性硬失效。
- **RMA 分析**：系统返回后，log 中的 syndrome 数据是芯片失效分析的重要依据。
- **UE 类型区分**：UE syndrome 可帮助区分 2-bit 错误与多 bit 错误，影响软件处理策略。

保留这些寄存器的软件成本极低（ISR 中多读一个寄存器），且软件可选择不读取。

## 3. 软件纠错流程

### 3.1 CE（1-bit 错误）处理

1. （可选）中断服务程序（ISR）收到 `int0`，读取 CE 寄存器组确认错误信息。
2. 软件将错误信息（Bank、阵列、entry 号、syndrome、发生时间等）记录到日志。
3. 清除中断标志。
4. **无需软件执行纠错写回**，硬件已完成 [^1]。

### 3.2 UE（2-bit 错误）处理

1. 中断服务程序（ISR）收到 `int2`，读取 UE 寄存器组确认错误信息。
2. 根据 `ERR_UE_BANK`、`ERR_UE_ARR_SEL` 和 `ERR_UE_ENTRY_ADDR` 定位错误位置。
3. 软件评估该条目的重要性，决定处理策略：
   - 若可重建 → 删除原条目，重新下发。
   - 若不可重建 → 标记该条目为无效，记录错误日志。
4. 清除中断标志。

> **注意**：若同一个 entry 的 Data 和 Mask 均有错误，软件可在一次读操作中同时修正，分别写回。UE 处理期间，软件应优先保证 `int2` 的中断响应延迟最小化。

## 4. 节流与定时控制

- **计数翻转触发**：`PATROL_INTERVAL` 寄存器配置两次巡检触发之间的时钟周期数，即计数器的计数值。计数器达到该值后翻转，触发一次巡检读操作 [^5]。
- **频率控制**：通过 `PATROL_INTERVAL` 可灵活控制巡检频率：
  - 值越小 → 巡检越频繁 → 错误发现窗口越小 → 功耗越高。
  - 值越大 → 巡检越稀疏 → 错误发现窗口越大 → 功耗越低。
- **反压计数**：可选的 `BACKPRESSURE_CNT` 寄存器记录被反压的次数，供软件评估巡检效率。

## 5. 关键设计考虑

### 5.1 Data/Mask 独立校验

由于 Data 和 Mask 是独立的 SRAM 阵列，分别具有独立的 ECC 校验位，因此每次触发必须分别读取两个阵列。每个 entry 的 ECC 域仅包含该阵列的存储位，不跨阵列。

### 5.2 全覆盖保证

由于每次触发后地址依次递增（0 → 1 → 2 → ... → N-1 → 0），只要 `PATROL_INTERVAL` 足够短以保证合理的循环周期，所有 entry 都能被定期覆盖，不存在检查盲区 [^3]。

### 5.3 回写原子性与写冲突

从检测到 CE 到完成回写，是一个不可中断的原子操作。硬件回写优先级最高，可反压流水线，确保回写操作的原子性 [^1]。

### 5.4 错误窗口

- **CE 场景**：硬件检测到 CE 后立即执行自动回写，错误窗口极小（仅数周期级），远小于软件纠错的毫秒级窗口。
- **UE 场景**：软件响应时间必须控制在系统容错范围内。建议将 `int2`（UE）的中断优先级设置为最高，确保快速响应。

### 5.5 外部 SRAM 的写掩码

外部 SRAM 必须支持**带写掩码的写入**。在设计 ECC Wrapper 时，需将 TCAM 阵列的写使能信号与 SRAM 的写掩码信号关联，确保只更新发生错误的阵列（Data/Mask）的校验位，不影响另一个。

## 7. 方案优势

- **中断分级处理**：CE 使用 `int0` 信息性中断，UE 使用 `int2` 致命中断，便于软件区分处理优先级。
- **硬件自动回写**：CE 由硬件自动纠正并回写，消除软件纠错延迟，极大缩小错误窗口 [^1]。
- **反压性能可控**：回写反压产生概率极低，性能损失可接受 [^1]。
- **全覆盖保证**：地址依次递增遍历所有 entry，不存在检查盲区 [^3]。
- **频率可配置**：通过 `PATROL_INTERVAL` 灵活平衡巡检频率与功耗 [^5]。
- **错误分类型独立记录**：CE 与 UE 使用独立的寄存器组，避免不同类型错误相互覆盖。
- **CE 计数功能**：CE 累计计数器用于监测硬件劣化趋势。
- **逐 entry 连续校验**：同一 entry 的 Data 和 Mask 连续校验完成，便于一次性处理两个阵列的错误。

## 1. 概述

本方案采用 **硬件检测 + 硬件自动纠错** 的设计思路。硬件通过计数翻转触发机制进行后台巡检：计数器计数到设定值后翻转，触发一次读操作，读取当前地址对应的一个 entry（Data + Mask），完成后地址递增，重新开始计数。当检测到 **1-bit 可纠正错误（CE）** 时，硬件自动执行纠错并写回原地址，无需软件干预。当检测到 **2-bit 不可纠正错误（UE）** 时，上报致命中断并由软件介入处理。

### 核心方案变更

- **ECC 校验位存储**：在 IP 外部集成一个带写掩码（Bit-Write Mask）的独立 SRAM，用于存储 Data 和 Mask 阵列的 ECC 校验位。该 SRAM 本身不额外做 ECC 校验 [^1]。
- **独立校验、统一存储**：Data 与 Mask 阵列分别独立计算 ECC 校验位，但校验位**统一**存储在上述外部 SRAM 中 [^1]。
- **硬件自动回写**：1-bit 错误由硬件检测到后立即自动纠正并写回阵列。回写优先级最高，可反压正常流水线访问 [^1]。
- **计数翻转触发**：计数器周期性地触发单次读操作，每次处理一个 entry，地址递增覆盖全部条目 [^2]。

### 中断分级

| 错误类型 | 中断等级 | 说明 |
|:--------:|:--------:|------|
| **1-bit 错误（CE）** | `int0`（信息性中断） | 硬件已自动纠正并回写，仅供软件记录归档 |
| **2-bit 错误（UE）** | `int2`（致命中断） | 不可纠正错误，需软件立即响应处理 |

## 2. 硬件架构

### 2.1 存储子系统

#### 2.1.1 ECC 校验位 SRAM

在 IP 外部实例化一个独立的 **带写掩码的 SRAM**，其规格如下：

| 参数 | 说明 |
|:----|:------|
| **深度** | 与 TCAM Data/Mask 阵列深度相同 |
| **宽度** | 由 Data 和 Mask 阵列的 ECC 校验位宽度之和决定（`ECC_WIDTH_DATA + ECC_WIDTH_MASK`） |
| **写掩码** | 支持字节/位级写掩码，用于回写时只修改指定阵列的校验位 |
| **ECC 保护** | 该 SRAM **不额外做 ECC 校验** [^1] |

#### 2.1.2 地址映射

- Data 阵列与 Mask 阵列的 ECC 校验位共享同一个外部 SRAM 的地址空间。
- 对于同一 entry，其 Data 和 Mask 阵列的校验位分别存储在 SRAM 地址的低位和高位（由硬件内部拼接）。
- 写入时，通过 SRAM 的写掩码功能，保证对 Data 或 Mask 的写入只影响对应的校验位区域。

### 2.2 巡检控制器 FSM

```
IDLE → [计数器翻转] → READ_DATA → CHECK_DATA → READ_MASK → CHECK_MASK → ADDR_INC → IDLE
                        ↓ (CE)            ↓ (CE)
                     [WRITE_BACK]      [WRITE_BACK]
```

- **IDLE**：等待计数器翻转（计数器持续计数时钟周期）。
- **计数器翻转**：计数器达到预设值 `PATROL_INTERVAL` 后翻转，触发一次巡检操作。
- **READ_DATA**：通过维护接口发出读请求，读取当前 `entry_addr` 指向的 Data 阵列数据，同时从外部 SRAM 读入其对应的 ECC 校验位。
- **CHECK_DATA**：
  - 无错误 → 直接进入 READ_MASK。
  - **CE（1-bit 错误）** → 进入 **WRITE_BACK_DATA** 状态，同时锁存错误信息。
  - **UE（2-bit 错误）** → 锁存错误信息，触发 `int2`，进入 READ_MASK。
- **WRITE_BACK_DATA**：将纠正后的数据与新的 ECC 校验位写回原地址。写回操作通过外部 SRAM 的写掩码接口进行，只更新 Data 阵列对应的校验位部分。完成后进入 READ_MASK。
- **READ_MASK**：通过维护接口发出读请求，读取当前 `entry_addr` 指向的 Mask 阵列数据及其对应的 ECC 校验位。
- **CHECK_MASK**：
  - 无错误 → 直接进入 ADDR_INC。
  - **CE（1-bit 错误）** → 进入 **WRITE_BACK_MASK** 状态，同时锁存错误信息。
  - **UE（2-bit 错误）** → 锁存错误信息，触发 `int2`，进入 ADDR_INC。
- **WRITE_BACK_MASK**：将纠正后的数据与新的 ECC 校验位写回原地址，只更新 Mask 阵列对应的校验位部分。完成后进入 ADDR_INC。
- **ADDR_INC**：递增 `entry_addr`（当 `entry_addr` 达到最大值后回绕至 0），复位计数器，跳回 IDLE 等待下一次翻转 [^2]。

### 2.3 地址生成与遍历顺序

- **共用地址计数器**：维护一个 `entry_addr`（0 ~ N-1，N 为每个阵列的 entry 深度），每次完成一次 Data + Mask 读操作后递增 1。
- **遍历顺序**：Data[t] → Mask[t] → Data[t+1] → Mask[t+1] → ... → Data[N-1] → Mask[N-1] → Data[0] → Mask[0] → ...，循环往复。
- **地址回绕**：当 `entry_addr` 递增超过 N-1 时，回绕至 0。
- **可配置参数**：
  - 起始/终止地址（支持子区间巡检）。
  - 步长（支持跳过配置，例如每巡检 N 条跳过 M 条）。

### 2.4 优先级与反压机制

#### 2.4.1 硬件回写优先级

- ECC 硬件的回写操作（`WRITE_BACK_DATA` / `WRITE_BACK_MASK`）在所有访问源中 **优先级最高** [^1]。
- 当硬件检测到 CE 并需要回写时，如果回写地址与当前流水线的读/写/搜索操作发生冲突，硬件 **反压流水线**（拉低 `ready` 信号），待回写完成后释放 [^1]。
- 考虑到 1-bit 错误发生概率极低，由此引起的性能损失是可接受的 [^1]。

#### 2.4.2 巡检读优先级

- 巡检过程中的读操作（`READ_DATA` / `READ_MASK`）优先级 **最低**，受以下约束：
  - 当软件通过维护接口读写 TCAM 时，巡检 READ 请求被 **反压**（hold，等待接口释放后重新发出）。
  - 当 TCAM 正在进行搜索操作时，巡检 READ 同样被反压。
  - 当 TCAM 正在进行 valid reset、flush 等维护操作时，巡检 READ 被反压。
- 巡检控制器在 IDLE 状态下持续检测维护接口的忙状态，仅当接口空闲时才启动 READ。

#### 2.4.3 反压实际影响评估

目前系统运行频率 930MHz，包率为 905MHz，即使在满流水状态也有约 25MHz（约 2.7%）的空闲周期。软件访问周期时间长，发生巡检一直反压的场景概率极低 [^3]。因此反压机制保留作为兜底保护，无需设计复杂的冲突仲裁逻辑。

### 2.5 ECC 编解码与外部 SRAM 交互

- **读路径**：
  1. 从 TCAM 阵列读出数据（Data/Mask）。
  2. 从外部 SRAM 读出对应的 ECC 校验位。
  3. 数据与校验位送入 ECC 解码器，生成 syndrome 和错误标志。
- **写路径（回写）**：
  1. ECC 解码器纠正后的数据与原始数据一起，送入 ECC 编码器计算新的校验位。
  2. 纠正后的数据写回 TCAM 阵列。
  3. 新的校验位通过外部 SRAM 的**写掩码接口**，只更新对应阵列的校验位区域。

### 2.6 中断与错误记录

错误记录采用 **分类型独立寄存器** 设计：

- **CE（1-bit 错误）寄存器组**：
  - `ERR_CE_BANK`：错误所在 Bank 号。
  - `ERR_CE_ARR_SEL`：错误所在阵列（0=Data，1=Mask）。
  - `ERR_CE_ENTRY_ADDR`：错误 entry 号。
  - `ERR_CE_SYNDROME`：校正子（保留用于诊断分析 [^4]）。
  - `ERR_CE_COUNT`：CE 累计错误次数（软件读清，用于监测硬件劣化趋势）。
  - `ERR_CE_AUTO_CORRECTED`：状态位，指示 CE 已由硬件自动处理。

- **UE（2-bit 错误）寄存器组**：
  - `ERR_UE_BANK`：错误所在 Bank 号。
  - `ERR_UE_ARR_SEL`：错误所在阵列（0=Data，1=Mask）。
  - `ERR_UE_ENTRY_ADDR`：错误 entry 号。
  - `ERR_UE_SYNDROME`：校正子（保留用于区分 UE 类型 [^4]）。

- **中断触发**：
  - `int0`：CE 硬件回写完成后触发，仅供软件记录归档。
  - `int2`：UE 检测到后立即触发，软件需立刻响应。

- **锁存策略**：硬件采用 **先到先锁** 策略（锁存首个错误信息，后续错误被覆盖）。

- **CE 阈值告警**（可选）：当 `ERR_CE_COUNT` 超过可编程阈值时，可额外触发一次告警中断，提示硬件可能劣化。

### 2.7 校正子（Syndrome）的用途

虽然 CE 已被硬件自动纠正，UE 无法定位具体错误位，但保留 `ERR_CE_SYNDROME` 和 `ERR_UE_SYNDROME` 仍有以下价值 [^4]：

- **故障诊断**：通过 syndrome 模式可判断错误是否为固定位错误（如某条位线短路），辅助定位硬件缺陷。
- **劣化趋势分析**：统计不同 syndrome 值的分布，区分随机软错误 vs. 系统性硬失效。
- **RMA 分析**：系统返回后，log 中的 syndrome 数据是芯片失效分析的重要依据。
- **UE 类型区分**：UE syndrome 可帮助区分 2-bit 错误与多 bit 错误，影响软件处理策略。

保留这些寄存器的软件成本极低（ISR 中多读一个寄存器），且软件可选择不读取。

## 3. 软件纠错流程

### 3.1 CE（1-bit 错误）处理

1. （可选）中断服务程序（ISR）收到 `int0`，读取 CE 寄存器组确认错误信息。
2. 软件将错误信息（Bank、阵列、entry 号、syndrome、发生时间等）记录到日志。
3. 清除中断标志。
4. **无需软件执行纠错写回**，硬件已完成 [^1]。

### 3.2 UE（2-bit 错误）处理

1. 中断服务程序（ISR）收到 `int2`，读取 UE 寄存器组确认错误信息。
2. 根据 `ERR_UE_BANK`、`ERR_UE_ARR_SEL` 和 `ERR_UE_ENTRY_ADDR` 定位错误位置。
3. 软件评估该条目的重要性，决定处理策略：
   - 若可重建 → 删除原条目，重新下发。
   - 若不可重建 → 标记该条目为无效，记录错误日志。
4. 清除中断标志。

> **注意**：若同一个 entry 的 Data 和 Mask 均有错误，软件可在一次读操作中同时修正，分别写回。UE 处理期间，软件应优先保证 `int2` 的中断响应延迟最小化。

## 4. 节流与定时控制

- **计数翻转触发**：`PATROL_INTERVAL` 寄存器配置两次巡检触发之间的时钟周期数，即计数器的计数值。计数器达到该值后翻转，触发一次巡检读操作 [^5]。
- **频率控制**：通过 `PATROL_INTERVAL` 可灵活控制巡检频率：
  - 值越小 → 巡检越频繁 → 错误发现窗口越小 → 功耗越高。
  - 值越大 → 巡检越稀疏 → 错误发现窗口越大 → 功耗越低。
- **反压计数**：可选的 `BACKPRESSURE_CNT` 寄存器记录被反压的次数，供软件评估巡检效率。

## 5. 关键设计考虑

### 5.1 Data/Mask 独立校验

由于 Data 和 Mask 是独立的 SRAM 阵列，分别具有独立的 ECC 校验位，因此每次触发必须分别读取两个阵列。每个 entry 的 ECC 域仅包含该阵列的存储位，不跨阵列。

### 5.2 全覆盖保证

由于每次触发后地址依次递增（0 → 1 → 2 → ... → N-1 → 0），只要 `PATROL_INTERVAL` 足够短以保证合理的循环周期，所有 entry 都能被定期覆盖，不存在检查盲区 [^3]。

### 5.3 回写原子性与写冲突

从检测到 CE 到完成回写，是一个不可中断的原子操作。硬件回写优先级最高，可反压流水线，确保回写操作的原子性 [^1]。

### 5.4 错误窗口

- **CE 场景**：硬件检测到 CE 后立即执行自动回写，错误窗口极小（仅数周期级），远小于软件纠错的毫秒级窗口。
- **UE 场景**：软件响应时间必须控制在系统容错范围内。建议将 `int2`（UE）的中断优先级设置为最高，确保快速响应。

### 5.5 外部 SRAM 的写掩码

外部 SRAM 必须支持**带写掩码的写入**。在设计 ECC Wrapper 时，需将 TCAM 阵列的写使能信号与 SRAM 的写掩码信号关联，确保只更新发生错误的阵列（Data/Mask）的校验位，不影响另一个。

## 7. 方案优势

- **中断分级处理**：CE 使用 `int0` 信息性中断，UE 使用 `int2` 致命中断，便于软件区分处理优先级。
- **硬件自动回写**：CE 由硬件自动纠正并回写，消除软件纠错延迟，极大缩小错误窗口 [^1]。
- **反压性能可控**：回写反压产生概率极低，性能损失可接受 [^1]。
- **全覆盖保证**：地址依次递增遍历所有 entry，不存在检查盲区 [^3]。
- **频率可配置**：通过 `PATROL_INTERVAL` 灵活平衡巡检频率与功耗 [^5]。
- **错误分类型独立记录**：CE 与 UE 使用独立的寄存器组，避免不同类型错误相互覆盖。
- **CE 计数功能**：CE 累计计数器用于监测硬件劣化趋势。
- **逐 entry 连续校验**：同一 entry 的 Data 和 Mask 连续校验完成，便于一次性处理两个阵列的错误。

### 2.4.3 反压实际影响评估

基于当前系统运行参数，对巡检反压的实际影响进行量化评估：

- **空闲周期窗口**：系统运行频率 930MHz，包率 905MHz，即使在满流水状态下仍有约 **25MHz（约 2.7%）的空闲周期** [^3]。这些空闲周期足以容纳巡检读操作（每次仅读 1 个 entry 的 Data + Mask，约数周期即可完成）。
- **软件访问频率**：软件通过维护接口读写 TCAM 的操作周期较长（通常为数十到数百微秒级），对巡检的阻塞概率极低 [^3]。
- **巡检单次操作短小**：计数翻转触发方案中，每次翻转只处理一个 entry，不涉及长时间占用接口，更容易被调度到空闲间隙中完成。
- **反压回弹特性**：即使偶遇软件访问导致巡检被反压，巡检操作会自然 pause 并在接口释放后立即恢复，不会丢失或遗漏 [^2]。

**结论**：巡检反压在工作场景下概率极低，对系统功能无实质影响。反压机制保留作为兜底保护即可，无需设计复杂的冲突仲裁逻辑。

# TCAM ECC 校验方案（最终版 v2.2）

## 版本记录

| 版本 | 日期 | 变更说明 |
|:----:|:----:|:--------|
| v1.0 | 2026-07-13 | 初始方案：硬件检测 + 软件纠错，内部 ECC 校验位，定时全遍历巡检 |
| v2.0 | 2026-07-22 | 改为硬件检测 + 硬件自动纠错 + 回写，移除软件纠错流程，调整中断为信息性/致命 |
| v2.1 | 2026-07-24 09:30 | ECC 校验位移至外部带写掩码 SRAM，Data/Mask 独立校验统一存储，删除 FSM 中的 GAP 状态 |
| v2.2 | 2026-07-24 10:23 | 触发机制从定时全遍历巡检改为计数翻转触发，精简 FSM 不再包含 GAP，明确巡检读优先级最低、回写优先级最高，保留 Syndrome 用于诊断保留，新增巡检反压实际影响评估 |

## 1. 概述

本方案采用 **硬件检测 + 硬件自动纠错** 的设计思路。硬件通过计数翻转触发机制进行后台巡检：计数器计数到设定值后翻转，触发一次读操作，读取当前地址对应的一个 entry（Data + Mask），完成后地址递增，重新开始计数。当检测到 **1-bit 可纠正错误（CE）** 时，硬件自动执行纠错并写回原地址，无需软件干预。当检测到 **2-bit 不可纠正错误（UE）** 时，上报致命中断并由软件介入处理。

### 核心方案变更

- **ECC 校验位存储**：在 IP 外部集成一个带写掩码（Bit-Write Mask）的独立 SRAM，用于存储 Data 和 Mask 阵列的 ECC 校验位。该 SRAM 本身不额外做 ECC 校验 [^1]。
- **独立校验、统一存储**：Data 与 Mask 阵列分别独立计算 ECC 校验位，但校验位**统一**存储在上述外部 SRAM 中 [^1]。
- **硬件自动回写**：1-bit 错误由硬件检测到后立即自动纠正并写回阵列。回写优先级最高，可反压正常流水线访问 [^1]。
- **计数翻转触发**：计数器周期性地触发单次读操作，每次处理一个 entry，地址递增覆盖全部条目 [^2]。

### 中断分级

| 错误类型 | 中断等级 | 说明 |
|:--------:|:--------:|------|
| **1-bit 错误（CE）** | `int0`（信息性中断） | 硬件已自动纠正并回写，仅供软件记录归档 |
| **2-bit 错误（UE）** | `int2`（致命中断） | 不可纠正错误，需软件立即响应处理 |

## 2. 硬件架构

### 2.1 存储子系统

#### 2.1.1 ECC 校验位 SRAM

在 IP 外部实例化一个独立的 **带写掩码的 SRAM**，其规格如下：

| 参数 | 说明 |
|:----|:------|
| **深度** | 与 TCAM Data/Mask 阵列深度相同 |
| **宽度** | 由 Data 和 Mask 阵列的 ECC 校验位宽度之和决定（`ECC_WIDTH_DATA + ECC_WIDTH_MASK`） |
| **写掩码** | 支持字节/位级写掩码，用于回写时只修改指定阵列的校验位 |
| **ECC 保护** | 该 SRAM **不额外做 ECC 校验** [^1] |

#### 2.1.2 地址映射

- Data 阵列与 Mask 阵列的 ECC 校验位共享同一个外部 SRAM 的地址空间。
- 对于同一 entry，其 Data 和 Mask 阵列的校验位分别存储在 SRAM 地址的低位和高位（由硬件内部拼接）。
- 写入时，通过 SRAM 的写掩码功能，保证对 Data 或 Mask 的写入只影响对应的校验位区域。

### 2.2 巡检控制器 FSM

```
IDLE → [计数器翻转] → READ_DATA → CHECK_DATA → READ_MASK → CHECK_MASK → ADDR_INC → IDLE
                        ↓ (CE)            ↓ (CE)
                     [WRITE_BACK]      [WRITE_BACK]
```

- **IDLE**：等待计数器翻转（计数器持续计数时钟周期）。
- **计数器翻转**：计数器达到预设值 `PATROL_INTERVAL` 后翻转，触发一次巡检操作。
- **READ_DATA**：通过维护接口发出读请求，读取当前 `entry_addr` 指向的 Data 阵列数据，同时从外部 SRAM 读入其对应的 ECC 校验位。
- **CHECK_DATA**：
  - 无错误 → 直接进入 READ_MASK。
  - **CE（1-bit 错误）** → 进入 **WRITE_BACK_DATA** 状态，同时锁存错误信息。
  - **UE（2-bit 错误）** → 锁存错误信息，触发 `int2`，进入 READ_MASK。
- **WRITE_BACK_DATA**：将纠正后的数据与新的 ECC 校验位写回原地址。写回操作通过外部 SRAM 的写掩码接口进行，只更新 Data 阵列对应的校验位部分。完成后进入 READ_MASK。
- **READ_MASK**：通过维护接口发出读请求，读取当前 `entry_addr` 指向的 Mask 阵列数据及其对应的 ECC 校验位。
- **CHECK_MASK**：
  - 无错误 → 直接进入 ADDR_INC。
  - **CE（1-bit 错误）** → 进入 **WRITE_BACK_MASK** 状态，同时锁存错误信息。
  - **UE（2-bit 错误）** → 锁存错误信息，触发 `int2`，进入 ADDR_INC。
- **WRITE_BACK_MASK**：将纠正后的数据与新的 ECC 校验位写回原地址，只更新 Mask 阵列对应的校验位部分。完成后进入 ADDR_INC。
- **ADDR_INC**：递增 `entry_addr`（当 `entry_addr` 达到最大值后回绕至 0），复位计数器，跳回 IDLE 等待下一次翻转 [^2]。

### 2.3 地址生成与遍历顺序

- **共用地址计数器**：维护一个 `entry_addr`（0 ~ N-1，N 为每个阵列的 entry 深度），每次完成一次 Data + Mask 读操作后递增 1。
- **遍历顺序**：Data[t] → Mask[t] → Data[t+1] → Mask[t+1] → ... → Data[N-1] → Mask[N-1] → Data[0] → Mask[0] → ...，循环往复。
- **地址回绕**：当 `entry_addr` 递增超过 N-1 时，回绕至 0。
- **可配置参数**：
  - 起始/终止地址（支持子区间巡检）。
  - 步长（支持跳过配置，例如每巡检 N 条跳过 M 条）。

### 2.4 优先级与反压机制

#### 2.4.1 硬件回写优先级

- ECC 硬件的回写操作（`WRITE_BACK_DATA` / `WRITE_BACK_MASK`）在所有访问源中 **优先级最高** [^1]。
- 当硬件检测到 CE 并需要回写时，如果回写地址与当前流水线的读/写/搜索操作发生冲突，硬件 **反压流水线**（拉低 `ready` 信号），待回写完成后释放 [^1]。
- 考虑到 1-bit 错误发生概率极低，由此引起的性能损失是可接受的 [^1]。

#### 2.4.2 巡检读优先级

- 巡检过程中的读操作（`READ_DATA` / `READ_MASK`）优先级 **最低**，受以下约束：
  - 当软件通过维护接口读写 TCAM 时，巡检 READ 请求被 **反压**（hold，等待接口释放后重新发出）。
  - 当 TCAM 正在进行搜索操作时，巡检 READ 同样被反压。
  - 当 TCAM 正在进行 valid reset、flush 等维护操作时，巡检 READ 被反压。
- 巡检控制器在 IDLE 状态下持续检测维护接口的忙状态，仅当接口空闲时才启动 READ。

### 2.5 ECC 编解码与外部 SRAM 交互

- **读路径**：
  1. 从 TCAM 阵列读出数据（Data/Mask）。
  2. 从外部 SRAM 读出对应的 ECC 校验位。
  3. 数据与校验位送入 ECC 解码器，生成 syndrome 和错误标志。
- **写路径（回写）**：
  1. ECC 解码器纠正后的数据与原始数据一起，送入 ECC 编码器计算新的校验位。
  2. 纠正后的数据写回 TCAM 阵列。
  3. 新的校验位通过外部 SRAM 的**写掩码接口**，只更新对应阵列的校验位区域。

### 2.6 中断与错误记录

错误记录采用 **分类型独立寄存器** 设计：

- **CE（1-bit 错误）寄存器组**：
  - `ERR_CE_BANK`：错误所在 Bank 号。
  - `ERR_CE_ARR_SEL`：错误所在阵列（0=Data，1=Mask）。
  - `ERR_CE_ENTRY_ADDR`：错误 entry 号。
  - `ERR_CE_SYNDROME`：校正子（保留用于诊断分析 [^4]）。
  - `ERR_CE_COUNT`：CE 累计错误次数（软件读清，用于监测硬件劣化趋势）。
  - `ERR_CE_AUTO_CORRECTED`：状态位，指示 CE 已由硬件自动处理。

- **UE（2-bit 错误）寄存器组**：
  - `ERR_UE_BANK`：错误所在 Bank 号。
  - `ERR_UE_ARR_SEL`：错误所在阵列（0=Data，1=Mask）。
  - `ERR_UE_ENTRY_ADDR`：错误 entry 号。
  - `ERR_UE_SYNDROME`：校正子（保留用于区分 UE 类型 [^4]）。

- **中断触发**：
  - `int0`：CE 硬件回写完成后触发，仅供软件记录归档。
  - `int2`：UE 检测到后立即触发，软件需立刻响应。

- **锁存策略**：硬件采用 **先到先锁** 策略（锁存首个错误信息，后续错误被覆盖）。

- **CE 阈值告警**（可选）：当 `ERR_CE_COUNT` 超过可编程阈值时，可额外触发一次告警中断，提示硬件可能劣化。

### 2.7 校正子（Syndrome）的用途

虽然 CE 已被硬件自动纠正，UE 无法定位具体错误位，但保留 `ERR_CE_SYNDROME` 和 `ERR_UE_SYNDROME` 仍有以下价值 [^4]：

- **故障诊断**：通过 syndrome 模式可判断错误是否为固定位错误（如某条位线短路），辅助定位硬件缺陷。
- **劣化趋势分析**：统计不同 syndrome 值的分布，区分随机软错误 vs. 系统性硬失效。
- **RMA 分析**：系统返回后，log 中的 syndrome 数据是芯片失效分析的重要依据。
- **UE 类型区分**：UE syndrome 可帮助区分 2-bit 错误与多 bit 错误，影响软件处理策略。

保留这些寄存器的软件成本极低（ISR 中多读一个寄存器），且软件可选择不读取。

## 3. 软件纠错流程

### 3.1 CE（1-bit 错误）处理

1. （可选）中断服务程序（ISR）收到 `int0`，读取 CE 寄存器组确认错误信息。
2. 软件将错误信息（Bank、阵列、entry 号、syndrome、发生时间等）记录到日志。
3. 清除中断标志。
4. **无需软件执行纠错写回**，硬件已完成 [^1]。

### 3.2 UE（2-bit 错误）处理

1. 中断服务程序（ISR）收到 `int2`，读取 UE 寄存器组确认错误信息。
2. 根据 `ERR_UE_BANK`、`ERR_UE_ARR_SEL` 和 `ERR_UE_ENTRY_ADDR` 定位错误位置。
3. 软件评估该条目的重要性，决定处理策略：
   - 若可重建 → 删除原条目，重新下发。
   - 若不可重建 → 标记该条目为无效，记录错误日志。
4. 清除中断标志。

> **注意**：若同一个 entry 的 Data 和 Mask 均有错误，软件可在一次读操作中同时修正，分别写回。UE 处理期间，软件应优先保证 `int2` 的中断响应延迟最小化。

## 4. 节流与定时控制

- **计数翻转触发**：`PATROL_INTERVAL` 寄存器配置两次巡检触发之间的时钟周期数，即计数器的计数值。计数器达到该值后翻转，触发一次巡检读操作 [^5]。
- **频率控制**：通过 `PATROL_INTERVAL` 可灵活控制巡检频率：
  - 值越小 → 巡检越频繁 → 错误发现窗口越小 → 功耗越高。
  - 值越大 → 巡检越稀疏 → 错误发现窗口越大 → 功耗越低。
- **反压计数**：可选的 `BACKPRESSURE_CNT` 寄存器记录被反压的次数，供软件评估巡检效率。

## 5. 关键设计考虑

### 5.1 Data/Mask 独立校验

由于 Data 和 Mask 是独立的 SRAM 阵列，分别具有独立的 ECC 校验位，因此每次触发必须分别读取两个阵列。每个 entry 的 ECC 域仅包含该阵列的存储位，不跨阵列。

### 5.2 全覆盖保证

由于每次触发后地址依次递增（0 → 1 → 2 → ... → N-1 → 0），只要 `PATROL_INTERVAL` 足够短以保证合理的循环周期，所有 entry 都能被定期覆盖，不存在检查盲区 [^3]。

### 5.3 回写原子性与写冲突

从检测到 CE 到完成回写，是一个不可中断的原子操作。硬件回写优先级最高，可反压流水线，确保回写操作的原子性 [^1]。

### 5.4 错误窗口

- **CE 场景**：硬件检测到 CE 后立即执行自动回写，错误窗口极小（仅数周期级），远小于软件纠错的毫秒级窗口。
- **UE 场景**：软件响应时间必须控制在系统容错范围内。建议将 `int2`（UE）的中断优先级设置为最高，确保快速响应。

### 5.5 外部 SRAM 的写掩码

外部 SRAM 必须支持**带写掩码的写入**。在设计 ECC Wrapper 时，需将 TCAM 阵列的写使能信号与 SRAM 的写掩码信号关联，确保只更新发生错误的阵列（Data/Mask）的校验位，不影响另一个。

### 5.6 巡检反压实际影响评估

基于当前系统运行参数，对巡检读操作反压的实际影响进行量化评估 [^3]：

- **空闲周期窗口充裕**：系统运行频率 930MHz，包率 905MHz，即使在满流水状态下仍有约 **25MHz（约 2.7%）的空闲周期**。这些空闲周期足以容纳巡检读操作（每次仅读 1 个 entry 的 Data + Mask，约数周期即可完成）。
- **软件访问频率极低**：软件通过维护接口读写 TCAM 的操作周期较长（通常为数十到数百微秒级），对巡检的阻塞概率极低。
- **巡检单次操作短小**：计数翻转触发方案中，每次翻转只处理一个 entry，不涉及长时间占用接口，更容易被调度到空闲间隙中完成。
- **反压回弹特性**：即使偶遇软件访问导致巡检被反压，巡检操作会自然 pause 并在接口释放后立即恢复，不会丢失或遗漏。

**结论**：巡检读操作反压在工作场景下概率极低，对系统功能无实质影响。反压机制保留作为兜底保护即可，无需设计复杂的冲突仲裁逻辑。

## 7. 方案优势

- **中断分级处理**：CE 使用 `int0` 信息性中断，UE 使用 `int2` 致命中断，便于软件区分处理优先级。
- **硬件自动回写**：CE 由硬件自动纠正并回写，消除软件纠错延迟，极大缩小错误窗口 [^1]。
- **反压性能可控**：回写反压产生概率极低，性能损失可接受 [^1]。
- **巡检反压风险极低**：基于系统运行频率和包率分析，巡检读反压概率极低，不影响正常流水线操作 [^3]。
- **全覆盖保证**：地址依次递增遍历所有 entry，不存在检查盲区 [^3]。
- **频率可配置**：通过 `PATROL_INTERVAL` 灵活平衡巡检频率与功耗 [^5]。
- **错误分类型独立记录**：CE 与 UE 使用独立的寄存器组，避免不同类型错误相互覆盖。
- **CE 计数功能**：CE 累计计数器用于监测硬件劣化趋势。
- **逐 entry 连续校验**：同一 entry 的 Data 和 Mask 连续校验完成，便于一次性处理两个阵列的错误。
