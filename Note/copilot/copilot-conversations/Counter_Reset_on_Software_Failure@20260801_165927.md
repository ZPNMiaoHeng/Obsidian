## 一、请求源

- **流水线查表请求** `pl_search_req`
- **软件请求** `sw_req`：读、写、search TCAM
- **TCAM_ECC_FSM 请求**：
  - 写请求：ECC 1-bit 错误回写正确数据，优先级最高；
  - 读请求：巡检读 TCAM 数据用于 ECC 校验检查，优先级最低

> **说明**：搬移/清除请求**不是独立 ARB 请求源**——由软件寄存器配置触发、独立于 ARB 仲裁。其互斥性由硬件 `move_busy` 互锁 + 软件限制条款双重保障。

---

## 二、仲裁优先级

1. **TCAM_ECC_FSM 写请求**，优先级最高（搬移期间经巡检读阻断不产生新写回，见 §七）；
2. **流水线查表请求 vs 软件请求**：
   - 默认流水线查表请求优先级高于软件请求；
   - 内部实现计数器 + 配置寄存器，支持**机会式调度**与**饿死保护**；
3. **TCAM_ECC_FSM 读请求**（巡检），优先级最低。

---

## 三、move_busy 硬件互锁

搬移/清除不经过 ARB 仲裁，但**物理占用 TCAM 接口**，在ARB外层新增mux，访问使用哪个，本质上都是软件访问。为降低"可信软件假设"的依赖，增加硬件最终防线：

- 搬移 FSM 输出 **`move_busy`** 广播至 ARB；
- `move_busy` 有效期间，ARB **硬件强制 stall** 以下请求源的 grant：
  - **软件请求**（不依赖软件自觉遵守"搬移期间不下发命令"）；
  - **ECC 巡检读**（从源头阻断 ECC 写回触发链）；
- `move_busy` 期间**计数器暂停**，搬移完成恢复计数（避免"触发但无法 grant"的无效中间态）。

| 请求源 | 与 move 的协调机制 | 来源 |
|:---|:---|:---:|
| 流水线查表 | `pipeline_conflict`（搬移 FSM 自行避让流水线） | 已有 |
| 软件请求 | `move_busy` stall ARB grant（硬件互锁） | 本轮新增 |
| ECC 巡检读 | `move_busy` stall ARB grant（阻断写回触发链） | 本轮新增 |
| ECC 写回 | 由巡检读阻断天然规避，无需独立握手 | 本轮新增 |

## 四、计数器实现

| 项目 | 设计 |
|:---|:---|
| 信号定义 | **`sw_waiting := sw_req_valid && !sw_grant && !move_busy`**（显式定义，消除实现二义性） |
| 加 1 条件 | `sw_waiting` |
| 清 0 条件 | 软件访问成功（`sw_grant`）；**行为 (b) 命令失效（`sw_discard`）后清 0 重新计数** |
| 暂停条件 | `move_busy`（搬移期间不计时） |
| 阈值触发 | `cnt >= csr_timeout_timer`（8bit 配置） |
| 饱和行为 | 达到阈值后**不再 +1，保持原值**，直到软件访问成功或命令失效才清 0；**饱和计数，非回绕计数** |

## 五、行为触发（配置可选，互斥）

配置寄存器：

- `csr_timeout_timer`：8bit 超时阈值；
- `csr_timeout_pressure_pipeline_en`：
  - 1'b1，**行为 (a)**；
  - 1'b0，**行为 (b)**；

### 行为 (a)：反压流水线 1 拍

- 触发条件：`sw_starved && sw_waiting && blocked`（有更高优先级请求占用接口，且软件确实被压制）；
- 反压窗口：**固定 1 拍**（有界，非"直到软件完成"）；
- 反压 1 拍后 grant 软件，软件访问完成（读已确认为 1 拍）；
- **触发当拍临时屏蔽 ECC 写回抢占**：保证"反压 1 拍 → 软件必然 grant"的有界性承诺，不受 ECC 写回连续到达影响（如多个 1-bit 错误并发、阵列局部失效）；
- 屏蔽逻辑仅在行为 (a) 触发当拍有效，不改变 ECC 写回的最高优先级属性。

### 行为 (b)：软件命令失效

- 触发条件同 (a)；
- 通过 `sw_discard` **物理握手信号**通知源端命令已失效，源端撤销请求（**与 ARB 同时钟域，无需 CDC 处理**）；
- 置于 `SW_STARVED` 状态：命令失效后计数器**清 0 重新计数**，重试命令须重新累计超过 `csr_timeout_timer` 阈值后才可再次触发行为，直到某次访问真正成功才清 0 退出；
- **退出条件**（防止软件永不重试导致死锁）：
  - `!sw_req_valid` 持续 `csr_starved_exit_cycles` 拍后退出 `SW_STARVED`；或
  - 新请求到达时重置等待窗口。

```
IDLE ──(cnt 越界 && sw_waiting)──▶ SW_STARVED
SW_STARVED ──(sw_grant)──▶ IDLE          // 访问成功，计数器清 0
SW_STARVED ──(sw_waiting && blocked && cnt 再次越界)──▶ 执行行为（a 强占 / b 失效）
  // 行为 (b) 执行：sw_discard 通知源端，计数器清 0，停留 SW_STARVED 等待源端重试
SW_STARVED ──(!sw_req_valid 持续 N 拍)──▶ IDLE  // 超时退出，计数器保持当前值
SW_STARVED ──(新请求到达)──▶ 重置等待窗口
```

> **v2.1 变更说明**：行为 (b) 执行（`sw_discard`）后计数器**清 0**，重试请求须重新从 0 累计满超时阈值才可再次触发行为，避免"重试立即再次失效"的活锁风险 [^1]。

### 机会式调度（默认路径）

流水线天然存在空拍（包间隙、hash 冲突、后端反压），当 `pl_req == 0` 时直接 grant 软件，**零性能损失**。超时行为仅在流水线持续满负荷超过阈值时触发，反压频率趋近于零。

## 六、接口协议约束

- **保持协议**：源端 valid 在反压期间**禁止撤销**，必须保持到收到 grant（或 `sw_discard`）；
- **读操作接口占用 1 拍**，数据延迟走输出路径不影响反压窗口，固定 1 拍反压窗口充分；
- 无需 skid buffer——保持协议下在途请求不丢失，仅在源端等待；
- **`sw_discard` 与 ARB 同时钟域**，无需同步器，直接物理连线。

---

## 七、搬移 FSM 与 ECC 的接口协调（重构）

### 7.1 触发链阻断机制（取代 move_if_busy 握手）

ECC 写回不是独立异步请求源，其唯一触发链路为：

```
巡检读（源头）→ CE 检测 → 写回
```

设计验证结论：**搬移期间 ECC 巡检读不发起，则该链路在源头被阻断，写回请求不可能产生**。

实现基础：

1. `move_busy` 有效期间，ARB **不 grant ECC 巡检读**（见 §三）；
2. 巡检读被阻止发起 → 无新 CE 检测 → 无新写回 → **写回与搬移的接口竞争天然不存在**；
3. 因此**无需 `move_if_busy` 写回级握手**——互锁点已从"写回"前移至"巡检读"。

### 7.2 在途巡检读边界场景（写回挂起）

巡检 FSM 若在搬移启动**前一拍**已发出读请求，数据返回与 CE 检测会落在搬移窗口内：

- 该巡检读合法，无需规避；
- 若检测出 CE，**写回请求挂起等待 `move_busy` 撤销后再执行**，不抢占搬移接口；
- 实现简单：写回 FSM 增加 `wait !move_busy` 条件，与现有挂起机制天然兼容。

### 7.3 与搬移 FSM 现有机制的关系

| 机制 | 作用 | 状态 |
|:---|:---|:---:|
| `pipeline_conflict` | 搬移 FSM 避让流水线查询 | 已有 |
| `move_busy` stall 软件 grant | 硬件互锁，替代纯软件约束 | 本轮新增 |
| `move_busy` stall 巡检读 grant | 阻断 ECC 写回触发链 | 本轮新增 |
| 写回挂起 | 处理在途巡检读的 CE 结果 | 本轮新增 |

## 八、优先级全景图（两层仲裁机制）

| 优先级 | 请求源 | 仲裁层级 | 与搬移的协调 |
| :-: | :------ | :----- | :--- |
| 1 | ECC 写回 | ARB | 搬移期间经巡检读阻断，不产生新写回；在途结果挂起避让 |
| 2 | 流水线查表 | ARB | 搬移 FSM 通过 `pipeline_conflict` 自行避让 |
| 3 | 搬移操作 | 搬移 FSM 内部（不进 ARB） | — |
| 4 | 软件请求 | ARB（带饿死计数器） | `move_busy` 期间硬件 stall grant |
| 5 | 清除操作 | 搬移 FSM 内部（不进 ARB） | — |
| 6 | ECC 巡检读 | ARB（最低） | `move_busy` 期间硬件 stall grant |

**边界清晰**：ARB 只管流水线/软件/ECC 三类请求源；搬移 FSM 自行管理其 TCAM 接口占用，`move_busy` 广播提供硬件互锁，无需逐请求源独立握手。

## 九、寄存器汇总

| 寄存器                                | 位宽  | 描述                                      |
| :--------------------------------- | :-: | :-------------------------------------- |
| `csr_timeout_timer`                |  8  | 饿死保护阈值（建议复位默认非 0，如 `8'hFF`）             |
| `csr_timeout_pressure_pipeline_en` |  1  | 1'b1，行为 (a)；1'b0，行为 (b)                 |
| `csr_starved_exit_cycles`          |  8  | 行为 (b) 中 `SW_STARVED` 退出超时阈值（N 拍无请求后退出） |

**计数器特性汇总**：饱和计数（非回绕）；`sw_grant` 清 0；**行为 (b) 命令失效（`sw_discard`）后清 0 重新计数**；`move_busy` 暂停；阈值态保持原值直到访问成功或命令失效。
