### 核心技术架构：Data + Mask 双阵列

手册设计的 TCAM 采用 **双 SRAM 阵列架构**（Data 阵列 + Mask 阵列）来编码三态值，而非传统 NOR 型 TCAM 的 16~18 个晶体管单元[^2]。

在 **12nm 工艺** 下，该架构借用成熟的 SRAM 编译器流程，单元面积更小、设计风险更低[^3]。

| Data | Mask | 含义 |
|:----:|:----:|:----:|
| 0 | 0 | **X**（Don't Care）— 比较时忽略 |
| 0 | 1 | **0** — 必须匹配 0 |
| 1 | 0 | **1** — 必须匹配 1 |
| 1 | 1 | **Prohibited** — 禁止状态（可作错误检测） |

比较逻辑为：`Match = (Data XOR Key) AND Mask`，即 Mask=0 时该位强制匹配，Mask=1 时要求 Key 与 Data 相等[^3]。

#### 关键特性

- **写掩码操作**：写入时可通过 MSKB 引脚逐位控制 Data 和 Mask 阵列，实现逐位修改，无需读出再修改整个字[^3]

**ai**: 根据手册及你的笔记，TCAM 的 **compare 实现** 基于 **Data + Mask 双阵列架构**，其核心比较逻辑如下：

### 核心比较逻辑

```text
Match = (Data XOR Key) AND Mask
```

- **Mask=0** 的位：该位强制匹配（Don't Care），无论 Data 与 Key 是否相等。
- **Mask=1** 的位：要求 Key 与 Data 严格相等，否则该位失配。

通过 Data 和 Mask 两个比特的组合，实现三态编码：

| Data | Mask | 含义 |
|:----:|:----:|:----:|
| 0 | 0 | **X**（Don't Care）— 比较时忽略 |
| 0 | 1 | **0** — 必须匹配 0 |
| 1 | 0 | **1** — 必须匹配 1 |
| 1 | 1 | **Prohibited** — 禁止状态（可作错误检测） |

### 查找操作流程

根据手册，TCAM 的查表操作需满足以下条件[^1]：

1. **CEB 为低**（芯片使能）
2. **CMP 为高**（比较模式）
3. **RST 为低**（非复位）
4. 只有 **valid 标志位为 1** 且对应的 **CBE（Bank Enable）为高** 的 entry 才会被用于比较。
5. 每个 entry 中 mask=0 的位在比较时被忽略。
6. 查表结果由 **ML[r-1:0]**（逐行匹配信号）输出。
7. 查表操作生效时，读、写操作均失效。

### 查找延迟

手册与项目笔记中明确，TCAM 的查找延迟分为两拍[^2]：

| 输出信号 | 延迟 | 说明 |
|---------|:----:|------|
| **HITLINE** (或ML[r-1:0]) | 1-cycle | 时钟上升沿触发比较后，下一拍即可得到哪些行匹配 |
| **HIT** (全局命中标志) | 2-cycle | 需要额外一拍才能得到最终结果 |

### 低功耗优化机制

双阵列架构还提供了多种降低比较功耗的手段[^3]：
- **Valid Bit 预过滤**：标记为无效的行直接跳过比较，避免不必要的动态功耗。
- **Bank 使能（CBE）**：通过配置 Bank Enable 引脚，仅激活部分阵列进行比较，整个 TCAM 阵列无需同时工作。

### 总结

TCAM 的 compare 实现本质上是**并行地、逐位地比较输入 Key 与每一个存储条目**，通过 Mask 字段实现灵活的三态匹配。查找结果在 1–2 个时钟周期内给出，并可通过 Valid Bit 和 Bank 使能来优化功耗。

**ai**: 根据手册及你的笔记，**MSKB（Mask Select Bit）** 是 TCAM 用于实现 **写入掩码（Bit-Write Mask）** 操作的关键控制引脚。

### 核心功能

MSKB 的作用是在写入 TCAM 时，**逐位控制 Data 阵列和 Mask 阵列是否被写入**[^1][^2]。它提供了**逐位修改**的能力，无需先读出再修改整个字。

### 工作方式

根据手册的写操作规范[^3]：

> 写 TCAM 时还需关注 **MASKB** 信号，**MASKB[i] 为 0 时，tcam_entry[i] 不会被写入**[^3]。

| MSKB[i] 值 | 对该位的影响 |
|:----------:|------------|
| **1** | 允许写入该位（Data 或 Mask） |
| **0** | **屏蔽写入**，该位保持不变 |

### 典型应用场景

1. **精确更新特定字段**：当需要修改 TCAM 表项中某几个字段（例如只更新掩码而不动数据，或反过来），可通过 MSKB 屏蔽不需要修改的位，实现精细化的局部更新。
2. **与 MD 信号配合**：手册中提到，写入时由 **MD** 区分是写 Data 还是写 Mask（Data 和 Mask 不能同时写）[^3]。MSKB 则进一步控制每个 bit 是否写入，两者配合实现灵活的写入控制。
3. **Valid Bit 写入**：写 valid 位时必须伴随 data 或 mask 一起写，且不可单独写[^3]。MSKB 可用于在这种复合写入场景中屏蔽不需要修改的部分。

### 总结

MSKB 提供了一个**位级写入保护机制**，允许软件在更新 TCAM 表项时，只修改特定比特，而保持其他比特不变。这在 **写掩码操作** 中非常关键，也是双阵列架构天然支持的优势之一——传统 NOR 型 TCAM 要实现类似功能要复杂得多[^1]。

**ai**: 根据手册第 11 页的 IO 表格说明，**MSKB 在比较操作（compare）中同样发挥作用**，其功能如下：

| 场景 | MSKB[i] 值 | 行为 |
|:----:|:----------:|------|
| **比较操作** | **1**（掩码禁用） | 列[i] 中所有 TCAM 位**被包含**在比较中 |
| **比较操作** | **0**（掩码使能） | 列[i] 中所有 TCAM 位**被排除**在比较之外 |

在比较模式下，MSKB 相当于一个**列级别的筛选器**，配合 Data/Mask 完成更精细的查找控制。主要应用场景包括：

1. **部分字段忽略**：当需要查找 key 时，可以通过将某些列的 MSKB 置 0，让这些列不参与比较，从而只在指定字段上进行匹配。

2. **宽度适配**：当 TCAM 实例宽度（bit）大于实际 key 宽度时，多余位的 Data/Mask 配置为 X（Don't Care），但通过 MSKB 显式排除这些列可以进一步减少不必要的比较功耗。

> **关键区别**：
> - **Mask 字段**（每个 entry 内部的 Mask 阵列）：控制的是**该条目**的某一位是否参与比较，粒度是**条目 × 位**。
> - **MSKB**（比较模式下）：控制的是**整列**的 TCAM 位是否参与比较，粒度是**全局 × 位**，影响所有 entry。

两者配合使用时，只有当 **MSKB[i]=1（该列使能）** 且 **该 entry 的 Mask[i]=1（该位非 Don't Care）** 时，才会真正比较 `Data[i]` 与 `Key[i]` 是否相等[^1]。
