**ai**: # ARB 模块设计介绍

## 一、功能说明

ARB 模块是 TCAM 的访问仲裁器，负责对以下三类请求源进行统一仲裁调度 [^1]：

1. **流水线查表请求** `pl_search_req`：业务报文的 TCAM 查表请求；
2. **软件请求** `csr_req`：CSR 链读、写、search TCAM；
3. **TCAM_ECC_FSM 请求**：
   - 写请求：ECC 1-bit 错误回写正确数据，**优先级最高**；
   - 读请求：巡检读 TCAM 数据用于 ECC 校验检查，**优先级最低**。

需要特别说明的是，**搬移/清除请求不是独立 ARB 请求源**——它们由软件寄存器配置触发，独立于 ARB 仲裁。其互斥性由硬件 `move_busy` 互锁 + 软件限制条款双重保障 [^1]。

模块核心功能可概括为三点：

- **两层仲裁**：ARB 只管流水线/软件/ECC 三类请求源；搬移 FSM 自行管理其 TCAM 接口占用，互不耦合；
- **机会式调度**：流水线存在天然空拍时直接 grant 软件请求，实现零性能损失；
- **饿死保护**：通过饱和计数器 + 配置寄存器，在软件请求持续被抢占时触发超时行为，保证软件可访问。

## 二、设计框图

```
                    ┌───────────────────────────────────────┐
                    │              ARB 模块                   │
                    │                                       │
  pl_search_req ────►│     ┌─────────────────────┐           │
                    │     │    ARB 仲裁核心       │           │
  csr_req ─────────►│     │ ① 优先级仲裁          │           │
                    │     │ ② 机会式调度          │──► TCAM  │
  ECC 巡检读 ───────►│     │ ③ 饿死保护计数        │   接口    │
                    │     └─────────────────────┘           │
                    │                                       │
  move_busy ────────►│   （硬件互锁：stall 软件请求            │
                    │    与 ECC 巡检读的 grant）             │
                    │                                       │
                    │     ┌─────────────────────┐           │
  ECC 写回 ─────────►│     │   外层 mux           │           │
                    │     │  ECC 写回无条件抢占    │──► TCAM  │
  搬移/清除操作 ─────►│     │  搬移操作             │   接口    │
                    │     └─────────────────────┘           │
                    └───────────────────────────────────────┘
```

对应的优先级全景图如下 [^1]：

| 优先级 | 请求源 | 仲裁层级 | 与搬移的协调 |
|:-:|:-:|:-:|:-:|
| 1 | ECC 写回 | ARB | 搬移期间经巡检读阻断，不产生新写回；在途结果直接抢占搬移 |
| 2 | 流水线查表 | ARB | 搬移 FSM 通过 `pipeline_conflict` 自行避让 |
| 3 | 搬移操作 | 搬移 FSM 内部（不进 ARB） | — |
| 4 | 软件请求 | ARB（带饿死计数器） | `move_busy` 期间硬件 stall grant |
| 5 | 清除操作 | 搬移 FSM 内部（不进 ARB） | — |
| 6 | ECC 巡检读 | ARB（最低） | `move_busy` 期间硬件 stall grant |

**边界清晰**：ARB 只管流水线/软件/ECC 三类请求源；搬移 FSM 自行管理接口占用，`move_busy` 广播提供硬件互锁，无需逐请求源独立握手 [^1]。

## 三、实现说明

### 3.1 move_busy 硬件互锁

搬移/清除不经过 ARB 仲裁，在 ARB 外层新增 mux，哪个请求有效，访问使用哪个。二者本质上都是软件访问。为降低"可信软件假设"的依赖，增加硬件最终防线 [^1]：

- 搬移 FSM 输出 **`move_busy`** 广播至 ARB；
- `move_busy` 有效期间，ARB **硬件强制 stall** 以下请求源的 grant：
  - **软件请求**（不依赖软件自觉遵守"搬移期间不下发命令"）；
  - **ECC 巡检读**（从源头阻断 ECC 写回触发链）；
- `move_busy` 期间**计数器暂停**，搬移完成恢复计数（避免"触发但无法 grant"的无效中间态）。

### 3.2 计数器实现

| 项目 | 设计 |
|:---|:---|
| 信号定义 | `sw_waiting := sw_req_valid && !sw_grant && !move_busy`（显式定义，消除实现二义性） |
| 加 1 条件 | `sw_waiting` |
| 清 0 条件 | 软件访问成功（`sw_grant`）；行为 (b) 命令失效（`sw_discard`）后清 0 重新计数 |
| 暂停条件 | `move_busy`（搬移期间不计时） |
| 阈值触发 | `cnt >= csr_timeout_timer`（8bit 配置） |
| 饱和行为 | 达到阈值后**不再 +1，保持原值**，直到软件访问成功或命令失效才清 0；**饱和计数，非回绕计数** [^2] |

### 3.3 行为触发（配置可选，互斥）

配置寄存器 `csr_timeout_pressure_pipeline_en`：

- **1'b1，行为 (a) 反压流水线 1 拍**：反压窗口**固定 1 拍**（有界，非"直到软件完成"），反压后等待流水线访问无效时 grant 软件，软件访问完成；
- **1'b0，行为 (b) 软件命令失效**：通过 `sw_discard` **物理握手信号**通知源端命令已失效，源端撤销请求，计数器清 0 重新计数。

### 3.4 机会式调度（默认路径）

流水线天然存在空拍（包间隙、hash 冲突、后端反压），当 `pl_req == 0` 时直接 grant 软件，**零性能损失**。超时行为仅在流水线持续满负荷超过阈值时触发，反压频率趋近于零。

### 3.5 接口协议约束

- **保持协议**：源端 valid 在反压期间**禁止撤销**，必须保持到收到 grant（或 `sw_discard`）；
- 读操作接口占用 1 拍，数据延迟走输出路径，不影响反压窗口；
- **无需 skid buffer**——保持协议下在途请求不丢失，仅在源端等待；
- **`sw_discard` 与 ARB 同时钟域**，无需同步器，直接物理连线。

### 3.6 搬移 FSM 与 ECC 的接口协调

**触发链阻断机制**（取代 move_if_busy 握手）[^1]：

```
巡检读（源头）→ CE 检测 → 写回
```

`move_busy` 有效期间 ECC 巡检读不发起，则该链路在源头被阻断，写回请求不可能产生。因此**无需 `move_if_busy` 写回级握手**——互锁点已从"写回"前移至"巡检读"。

**在途巡检读边界场景**：巡检 FSM 若在搬移启动**前一拍**已发出读请求，数据返回与 CE 检测落在搬移窗口内。该巡检读合法，若检测出 CE，写回请求以最高优先级直接抢占搬移接口，搬移被反压 [^1]。搬移 FSM 为**非原子性操作**，每个 T-cycle 都是独立完整操作，周期间的反压不破坏数据一致性——天然支持"被反压 → 保持当前状态 → 接口释放后恢复"的路径 [^3]。

### 3.7 可行性闭环结论

方案经多轮评审与可行性评估，三个实现期边界点已**全部关闭**，可进入 RTL 实现阶段 [^3]：

| 原关注点 | 关闭依据 | 状态 |
|:---|:---|:---:|
| 行为 (a) 反压后等待时间无界 | 全满负载下仍有系统余量（930MHz vs 905MHz，25MHz 余量），软件可访问 | ✅ 关闭 |
| 在途巡检读 CE 写回与搬移竞争 | 搬移 FSM 非原子、可接受外部反压，写回直接抢占即可 | ✅ 关闭 |
| mux 优先级需 RTL 显式化 | 优先级全景图已明确语义 | ✅ 关闭 |

**实现阶段无遗留阻塞项。**
