**ai**: “拆一半”并非严格的数学推导结论，而是工程实践中总结出的一个经验折中点 [^1]。其合理性体现在以下几个层面的权衡：

### 1. 面积与功耗的均衡点

Memory 拆分主要分为两种方式，效果完全不同 [^2]：

- **按宽度拆分**：面积增大，功耗也增大 —— 这是**双输**，工程中应避免 [^2]。
- **按深度拆分**：这是实际工程中使用的方向。拆分后总 **Leakage 功耗** 和 **Standby 功耗** 增大，但 **动态功耗** 减小 [^3]。

“拆一半”所处的区间往往是**动态功耗节省**与**面积/Leakage增加**的边际效益交叉点。再拆细（如拆成 4 份、8 份），动态节省会趋于饱和，但面积和漏电的代价却持续上升，收益递减。

### 2. 动态功耗理论下的成本效益比

拆分为 N 份后：
- **动态读/写功耗** 约降至 `1/N`（因为每次只激活 1 个 Bank）
- **Leakage 功耗** 增至约 `N × 单 Bank Leakage`（总晶体管数增加）
- **面积** 增加约 `N × 单 Bank 开销`（含 Bank 间隙和 BIST 电路）[^3]

当 `N=2` 时，动态功耗降低一半，而面积和漏电的增幅相对可控；继续增大 N，面积和漏电呈线性增长，动态功耗的边际收益却快速下降。

### 3. 后端物理实现的友好性

从 PR（Place and Route）角度：
- 拆成 2 个 Bank，布局时两个 SRAM 可并排摆放，绕线开销最低
- 拆成 4 个或更多 Bank 后，Bank 间间隙增多、绕线资源被碎片化，可能导致更多拥塞

### 4. 设计复杂度的控制

拆分后需要复制一份 Bank 选择逻辑、地址译码和数据选择逻辑。拆一半时这些逻辑的开销很小；拆得更细时，Bank 选择逻辑呈二叉树增长，验证复杂度也显著上升。

> **总结**：“拆一半”是一个综合考虑 **动态功耗节省、面积开销、漏电增长、后端实现和设计复杂度** 后的工程直觉。但文档也明确指出“不能普适所有情况” [^1]，实际应用中仍需根据工作频率、有效访问次数和功耗预算做具体评估。

# SRAM Bank 拆分分析

> **标签**：#IC
> **工艺**：T22nm（以下结论基于该工艺特征，其他工艺需重新评估）

## 1. 概述

本文档分析 SRAM Bank 拆分对**面积**和**功耗**的影响，并给出工程实践建议。核心结论：按深度拆分可降低动态功耗，但会增加面积、Leakage 和 Standby 功耗；“拆一半”是常见的经验折中点 [^1]。

## 2. 面积影响

Memory 拆分得越细，面积越大，面积增量来源于三个部分 [^2]：
- Memory 本身面积增大（总晶体管数增加）
- PR 摆放的间隙开销（Bank 间无法紧密排列）
- BIST 测试电路增加（每个 Bank 需要独立的测试接口）

## 3. 功耗影响

Memory 的功耗包含三项 [^3]：
- **Leakage 功耗**：静态泄漏电流
- **动态读写功耗**：每次访问时的充放电功耗
- **Standby 功耗**：非访问状态下的保持功耗

### 3.1 按宽度拆分

宽度拆分后，面积增大的同时功耗也增大 **—— 双输，工程中应避免** [^2]。

### 3.2 按深度拆分（工程常用方向）

| 功耗项 | 变化趋势 | 说明 |
|--------|----------|------|
| 总 Leakage 功耗 | **↑ 增大** | 总晶体管数增加 |
| Standby 功耗 | **↑ 增大** | 更多 Bank 需保持准备就绪 |
| 动态功耗 | **↓ 减小** | 每次仅激活 1 个 Bank |

动态功耗和 Standby 功耗跟工作频率和有效访问频率相关，需根据应用需求评估 [^3]。

## 4. 工程实践建议

- **拆一半常见但非普适**：实际工程中，拆一半是一个比较合适的选择，但不能普适所有情况 [^1]。
- **核心原则**：动态功耗节省与面积/Leakage 增加的边际效益交叉点通常在 `N=2` 附近，继续增加 Bank 数则收益递减。
- **低功耗优化**：应合理利用 Memory 的 **SD（关断模式）** 和 **SLP（休眠模式）** 功能，做到动态启用，尤其是 SD 在高温下对降低 Leakage 功耗效果显著 [^1][^3]。

# SRAM Bank 拆分分析

> **标签**：#IC
> **工艺**：T22nm（以下结论基于该工艺特征，其他工艺需重新评估）

## 1. 概述

在数字电路设计中，当需要实现大容量查找表或缓存时，常因单块 SRAM IP 核的规格限制，需要将整张表拆分为多个独立的 SRAM Bank 来实现。这不仅是绕过 IP 限制的必然选择，更是一种能带来功耗、性能和灵活性收益的优化策略。

本文档分析 SRAM Bank 拆分对**面积**、**功耗**、**性能**的影响，涵盖地址映射策略、收益与风险，并给出工程实践建议。核心结论：按深度拆分可降低动态功耗，但会增加面积、Leakage 和 Standby 功耗；"拆一半"是常见的经验折中点，但不能普适所有情况。

## 2. 地址映射策略

将大表拆分为多 Bank 后，最核心的问题是如何将地址映射到具体的 Bank。主要有以下三种方案：

| 方案 | 实现方式 | 优点 | 缺点 | 适用场景 |
|------|----------|------|------|----------|
| **低位交叉** | 用地址最低的 N 位选择 Bank | 连续地址轮换分布，顺序访问并发度高；逻辑开销几乎为零 | 对"步长=2^N"的访问模式敏感，易产生 Bank 冲突 | 流式处理、视频像素等顺序访问场景 |
| **高位交叉** | 用地址最高的 N 位选择 Bank | 地址空间连续，软件管理友好 | 局部性访问时并发度极低 | 分区管理、多任务隔离场景 |
| **哈希映射** | 将地址多位进行异或等运算后选 Bank | 有效打散不规则访问，抗冲突能力强 | 需额外逻辑门，破坏顺序访问的轮换特性 | 随机查表、路由查找、数据库索引等场景 |

> **设计建议**：优先分析实际工作负载的地址访问模式。若以顺序流式访问为主，直接用低位交叉是最优解；若为高随机性跳转访问，考虑引入轻量级哈希（如 XOR）以提升有效带宽。

- PR 摆放的间隙开销（Bank 间无法紧密排列）

## 4. 功耗影响

- **动态读写功耗**：每次访问时的充放电功耗
- **Standby 功耗**：非访问状态下的保持功耗

## 5. 多 Bank 拆分的收益

| 收益维度 | 说明 |
|----------|------|
| **绕开IP限制** | 突破单块 SRAM 的深度/宽度上限，实现大容量存储 |
| **降低动态功耗** | 每次操作仅激活目标 Bank，无需为整块大阵列供电 |
| **提升访问带宽** | 不同 Bank 可并行响应互不冲突的访问请求 |
| **提升工作频率** | 更小的 Bank 尺寸缩短位线长度，减少寄生负载，利于时序收敛 |

- 更多 Bank 意味着更多晶体管处于待机状态
- 更多 Bank 需保持准备就绪，Standby 功耗随之增加

### 6.3 动态功耗节省边际效益递减

虽然动态功耗随拆分而减小（每次仅激活 1 个 Bank），但当 N > 2 后，动态功耗的降低趋于饱和，而面积和漏电的代价持续上升，收益快速递减。

### 6.4 后端物理实现恶化

- 拆成 4 个或更多 Bank 后，Bank 间间隙增多，绕线资源被碎片化，可能导致拥塞
- 深拆分后 PR 布局的灵活度下降，时序收敛更困难

### 6.5 设计复杂度增加

拆分过多后，Bank 选择逻辑、地址译码和数据选择逻辑呈二叉树增长，设计验证复杂度显著上升。

### 6.6 小容量 Bank 定制效率低

当 Bank 深度过小（如 < 2K）时，SRAM 相比 Reg Table 没有面积优势，此时强行使用 SRAM 定制反而效率低下，更适合用 Reg Table 实现。

## 7. 工程实践建议

### 7.1 核心原则

- **拆一半常见但非普适**：实际工程中，拆一半是一个比较合适的选择，但不能普适所有情况。动态功耗节省与面积/Leakage 增加的边际效益交叉点通常在 N=2 附近，继续增加 Bank 数则收益递减。
- **低功耗优化**：应合理利用 Memory 的 **SD（关断模式）** 和 **SLP（休眠模式）** 功能，做到动态启用，尤其是 SD 在高温下对降低 Leakage 功耗效果显著。
- **同构拆分优先**：优先采用均匀规格的 Bank，便于后端布局布线的规整化。

### 7.2 推荐设计流程

1. **明确优化目标**：确定 PPA（Performance, Power, Area）三者的优先级排序
2. **使用 Memory Compiler 评估**：针对不同 Bank 配置，生成物理模型进行横向对比
3. **量化分析 PPA**：提取面积、访问时间、动态/静态功耗数据
4. **架构级仿真验证**：将各配置的时序和冲突模型代入 RTL 仿真，评估实际工作负载下的有效带宽与性能
5. **综合决策**：结合优化目标与仿真数据，选定最优配置

3. **BIST 测试电路增加**：每个 Bank 需要独立的 BIST 测试接口和控制器，拆分越多，BIST 逻辑的复制开销越大，进一步推升面积 [^1]。

> **本质原因**：SRAM 的面积并非与容量完全线性缩放，拆分会引入多个重复的"固定开销"（外围电路），这些固定开销的总和随 Bank 数量线性增长，而存储阵列本身的面积却因拆分而碎片化，无法再共享外围资源 [^1]。

# SRAM Bank 拆分分析

> **标签**：#IC
> **工艺**：T22nm（以下结论基于该工艺特征，其他工艺需重新评估）

## 1. 概述

在数字电路设计中，当需要实现大容量查找表或缓存时，常因单块 SRAM IP 核的规格限制，需要将整张表拆分为多个独立的 SRAM Bank 来实现。这不仅是绕过 IP 限制的必然选择，更是一种能带来功耗、性能和灵活性收益的优化策略。

本文档分析 SRAM Bank 拆分对**面积**、**功耗**、**性能**的影响，涵盖地址映射策略、收益与风险，并给出工程实践建议。核心结论：按深度拆分可降低动态功耗，但会增加面积、Leakage 和 Standby 功耗；"拆一半"是常见的经验折中点，但不能普适所有情况。

## 2. 地址映射策略

将大表拆分为多 Bank 后，最核心的问题是如何将地址映射到具体的 Bank。主要有以下三种方案：

| 方案 | 实现方式 | 优点 | 缺点 | 适用场景 |
|------|----------|------|------|----------|
| **低位交叉** | 用地址最低的 N 位选择 Bank | 连续地址轮换分布，顺序访问并发度高；逻辑开销几乎为零 | 对"步长=2^N"的访问模式敏感，易产生 Bank 冲突 | 流式处理、视频像素等顺序访问场景 |
| **高位交叉** | 用地址最高的 N 位选择 Bank | 地址空间连续，软件管理友好 | 局部性访问时并发度极低 | 分区管理、多任务隔离场景 |
| **哈希映射** | 将地址多位进行异或等运算后选 Bank | 有效打散不规则访问，抗冲突能力强 | 需额外逻辑门，破坏顺序访问的轮换特性 | 随机查表、路由查找、数据库索引等场景 |

> **设计建议**：优先分析实际工作负载的地址访问模式。若以顺序流式访问为主，直接用低位交叉是最优解；若为高随机性跳转访问，考虑引入轻量级哈希（如 XOR）以提升有效带宽。

## 3. 面积影响

Memory 拆分得越细，面积越大，面积增量来源于三个部分：
- Memory 本身面积增大（总晶体管数增加）
- PR 摆放的间隙开销（Bank 间无法紧密排列）
- BIST 测试电路增加（每个 Bank 需要独立的测试接口）

## 4. 功耗影响

Memory 的功耗包含三项：
- **Leakage 功耗**：静态泄漏电流
- **动态读写功耗**：每次访问时的充放电功耗
- **Standby 功耗**：非访问状态下的保持功耗

### 4.1 按宽度拆分

宽度拆分后，面积增大的同时功耗也增大 **—— 双输，工程中应避免**。

### 4.2 按深度拆分（工程常用方向）

| 功耗项 | 变化趋势 | 说明 |
|--------|----------|------|
| 总 Leakage 功耗 | **↑ 增大** | 总晶体管数增加 |
| Standby 功耗 | **↑ 增大** | 更多 Bank 需保持准备就绪 |
| 动态功耗 | **↓ 减小** | 每次仅激活 1 个 Bank |

动态功耗和 Standby 功耗跟工作频率和有效访问频率相关，需根据应用需求评估。

## 5. 多 Bank 拆分的收益

| 收益维度 | 说明 |
|----------|------|
| **绕开IP限制** | 突破单块 SRAM 的深度/宽度上限，实现大容量存储 |
| **降低动态功耗** | 每次操作仅激活目标 Bank，无需为整块大阵列供电 |
| **提升访问带宽** | 不同 Bank 可并行响应互不冲突的访问请求 |
| **提升工作频率** | 更小的 Bank 尺寸缩短位线长度，减少寄生负载，利于时序收敛 |

## 6. 过度拆分的风险与代价

> **说明**：以下"过度拆分"的警告阈值（N > 4）与第7章推荐拆分一半（N=2）并不矛盾。N=2是收益最大化的推荐折中点；而N > 4表示拆分到4份以上时，负面效应开始非线性加剧，属于应避免的过度拆分区间。

Bank 拆分并非越多越好，若 Bank 拆分过多（例如 N > 4），会带来以下问题：

### 6.1 面积显著增大

如第3节所述，拆分越细、面积越大，三个来源（Memory本身、PR间隙、BIST电路）都会随Bank数线性增长。当N > 4时，面积增量将非线性加剧，小Bank的"固定开销"占比远高于大Bank，导致总面积显著超出预期。

### 6.2 漏电与静态功耗上升

按深度拆分时，总 Leakage 功耗和 Standby 功耗随 Bank 数量线性增长：
- 更多 Bank 意味着更多晶体管处于待机状态
- 更多 Bank 需保持准备就绪，Standby 功耗随之增加

### 6.3 动态功耗节省边际效益递减

虽然动态功耗随拆分而减小（每次仅激活 1 个 Bank），但当 N > 2 后，动态功耗的降低趋于饱和，而面积和漏电的代价持续上升，收益快速递减。

### 6.4 后端物理实现恶化

- 拆成 4 个或更多 Bank 后，Bank 间间隙增多，绕线资源被碎片化，可能导致拥塞
- 深拆分后 PR 布局的灵活度下降，时序收敛更困难

### 6.5 设计复杂度增加

拆分过多后，Bank 选择逻辑、地址译码和数据选择逻辑呈二叉树增长，设计验证复杂度显著上升。

### 6.6 小容量 Bank 定制效率低

当 Bank 深度过小（如 < 2K）时，SRAM 相比 Reg Table 没有面积优势，此时强行使用 SRAM 定制反而效率低下，更适合用 Reg Table 实现。
