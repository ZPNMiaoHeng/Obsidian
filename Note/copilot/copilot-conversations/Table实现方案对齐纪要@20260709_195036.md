# 会议纪要：Table 实现方案对齐

## 一、 会议结论
- **URPF 策略**：支持全局配置与动态配置。开启后，表项规格减半。
  - **同步风险**：重点关注配置动态切换的逻辑，防止出现切换期间业务挂死。
- **L3_ECMP_A 实例化**：该表需分别在 L3 模块和 ICAP 模块中实例化。
  - **CSR 访问方案**：采用 CSR 组播配置方式实现读写。虽有串链物理延迟，但功能上完全可接受。

## 二、 遗留问题
- **L3 组播查询机制**
  - **验证场景**：需要与软件确认使用场景，例如，连续查三次是否会限速至三分之一，以及 Bank 内是否会有混合配置。
  - **设计倾向**：硬件实现倾向于功能划分到 Bank 粒度。
  - **待对齐事项**：友商单播规格需与软件确认；需构建特定组播报文测试场景，确保单报文多次查表获取组播号。
- **ING_L3_NEXT_HOP 与 DLB 处理**
  - **ING_DVP_TABLE** 重定向在 ICAP 中实现。
  - **DLB 合并可行性**：需评估 ICAP 与 L3 中的两次 DLB 是否可合并为 ICAP 内一次。需分析此方案的影响和实现是否可接受。
  - **备选实现**：在 L3 和 ICAP 分别做标记，后续再实现一次 DLB 查找。
- **SRAM 类型调整**：拟将类型修改为 SPRAM。
- **MPLS 查询性能**
  - **需求分析**：目前协议和软件需求倾向查询多次，但硬件上，查询两次将导致性能减半，整体方案待定。
  - **设计与验证**：需权衡设计实现与性能诉求；分析 8002、8120 等芯片的 MPLS 性能，考量其对多层标签处理、整机转发的实际影响和测试情况。
- **VLAN_XLATE 模糊插线**：评估精确查询、模糊插线功能开启后，是否会有性能损失，需确认 8120 开启后是否有约束。
- **IFIT_Record_tx_t 实现**：1R1W 实现方案已确认。
- **交互与协作待办**
  - 明确 L3 entry multicast 的软件对齐和使用场景。
  - 全朝辉推进 MPLS Nov3 两次查询合并的可能性。
  - 陈然跟进 8002、8120 相关功能的测试与性能反馈。
